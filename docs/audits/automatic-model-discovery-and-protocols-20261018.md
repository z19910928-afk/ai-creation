# 自动获取模型与接入方式验收

日期：2026-10-18。

## 产品行为

参考 [NovelForge 的模型配置表单](https://github.com/RhythmicWave/NovelForge/blob/a485814411546b3980df0a1696a0fb6a043d56ce/frontend/src/renderer/src/components/setting/LLMConfigForm.vue)，主模型库与写作总管均提供服务地址、密钥、接入方式和可搜索的模型下拉框。

- 填好连接后自动查询模型清单，连续输入合并为一次查询；也可手动刷新。支持多个模型、键盘选择、搜索和手动填写。
- 查询清单只读取服务的模型目录，不生成内容、不保存连接、不占用生成额度，不自动选中第一项。仍需逐个测试，通过后保存，再分配用途。
- 支持通用兼容 Chat 与 Responses 两种实际协议。基础地址、完整 `/chat/completions` 和 `/responses` 地址均归一到相应端点。
- 协议随连接保存，贯穿用途、独立或继承的总管对话、冻结队列、重试与候选整理。旧配置缺少协议时继续使用 Chat。
- Responses 使用原生请求、JSON 和流式事件，正文、结束状态与用量分别核对；工具调用、拒绝、截断、断流与取消不冒充完整正文。
- Responses 用途按实际继承参数验证，输出长度至少为 16，不兼容的 Chat 参数在发送前拒绝。连接库的测试使用独立探测参数，避免旧 Chat 参数阻止新增 Responses 模型。
- 更改协议或连接信息撤销旧测试资格。保存后的连接不会继续自动重复查询；重新编辑时可再次获取。
- 离页、切作品、清除或修改密钥、修改地址会取消旧查询；迟到的清单不会覆盖新表单。未保存密钥不写浏览器存储。
- 已存密钥只允许同一个规范化服务地址沿用。更换主机、端口或 API 路径后，前端提示重新填写，后端在查询、测试和总管保存时同样阻止静默复用。明确新密钥或明确免密的本机服务可继续。
- 现代任务的完整请求、协议、端点、消息及请求指纹在发送前重建核验；删除审计或篡改请求均拒绝外发并释放未使用额度。
- 完整作品备份保留协议及兼容选项，仍移除密钥、旧测试资格和用途绑定，恢复后重新验证。

## 本机预览与发布边界

本机预览已加载新版。重启前创建并核验 SQLite 一致快照；重启并打开模型设置后，原数据库 72 张表及结构的指纹均保持一致，聊天输入草稿保留。原作品未写入模拟模型设置。

本记录是本轮本机验证结果，GitHub 完整检查以对应提交的 Actions 结果为准。源码及本机预览更新不等于安装包更新；此前发布的 `v0.1.0` 安装包不包含本轮修改。

本轮只实现上述两种协议，未增加其他厂商的原生协议。模型目录由配置的服务提供，未提供目录时可手填并测试。连接测试与工程回归不能证明底层模型身份、文学质量或第一梯队排名。
