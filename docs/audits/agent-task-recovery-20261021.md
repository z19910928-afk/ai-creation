# 写作总管任务中断恢复验收

日期：2026-10-21。基线：`df9d710`，工作分支：`codex/repository-layout`。本轮继续修复常驻写作总管的任务恢复与规划定位，不更换模型、不增加付费评测、不改作者作品。

## 两种断线情况

此前已覆盖“本机服务完成操作，浏览器没有收到回应”，但没有覆盖“请求根本没有到达本机服务”。后者精确读取仍会返回同一状态和检查点，本机持久化的待核对标记不会消失，原启动、确认和采用按钮也不会恢复。

本轮新增明确的手动恢复路径：

1. 发起原步骤前，在本机保存操作种类、原检查点、状态及任务身份；规划同时保存工作流、版本、候选编号与候选校验值。
2. 网络失联后只读取原任务。刷新、轮询、切聊天和服务恢复都不会自动重发生成请求。
3. 原身份仍一致时显示“核对并重试原步骤”，并说明是否会生成下一阶段、是否可能消耗当前模型额度。
4. 作者点击后先保存本页草稿，再精确读取原任务。状态、检查点、候选或来源变化时停止；切换聊天、作品或分支后，迟到结果不能继续操作。
5. 仍是原步骤时只发送相同操作与相同检查点。本机服务在同一数据库事务中验证检查点并保存进度，原请求与恢复请求重叠也只提交一次，随后才派发生成任务。

正文生成、作者采纳、章后资料确认和完整规划采用仍分别处理；恢复不会自动采纳正文或确认正典。执行结果未知、来源过期、历史只读、身份不符的任务不会因为这个入口取得生成权限。

## 规划历史保护补修

明确指定的规划记录不存在时，保留原选中编号，而不是把选中清空。再次读取、切到其他页面后返回都继续显示缺失提示，只有作者点击“查看当前最新规划”才允许打开最新记录。

读取规划列表前捕获当前选中，回应到达时选中已经变化则放弃旧回应，避免迟到列表覆盖作者正在查看的记录；切作品时清除旧作品的缺失提示。

后端新增并发检查：启动、阶段确认、完整采用各由两个线程同时提交同一检查点，只产生一次状态变化和一次对应派发；采用不派发生成。全部完成后再次重放三个旧检查点，返回原任务最新状态，整库快照不变。正文启动的旧检查点在候选完成后重放同样不改变数据库。
