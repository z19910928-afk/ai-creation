# 写作总管任务步骤与成果预览复核

日期：2026-10-21。范围：主页面右侧常驻写作总管的写作任务卡，覆盖可核对的真实步骤、规划与正文成果预览、重绘后的展开与滚动状态，以及与规划确认、完整采用、作者采纳的衔接。

## 改动内容

- 任务卡按真实步骤展示状态（尚未开始、排队中、正在生成、生成完成、候选待确认、作者采纳、已失败、待核对等）；续写与润色任务单独显示“作者采纳正文”节点，正文生成成功不再显示为已采纳。
- 规划候选按中文标签（故事核心、题材、读者、基调、创作约定、核心冲突、主角、标题、梗概、分卷、章节、场景等）递归预览，可展开查看完整规划；正文候选可展开预览原文，模型成果统一转义，不产生可执行 HTML 或链接。
- 手动核对任务进度与聊天轮询重绘后，保留作者展开的折叠面板状态及预览内部滚动位置；操作结果未知时提示“操作结果待核对”，不重复执行。
- 完成对话中的规划确认、完整规划采用与正文采纳衔接；采用后进入“检查通过后归档本章”的就绪状态，不重新授权或启动模型。
- 补齐对应浏览器回归：常驻聊天 30 条、写作流程 10 条、写作工作台 19 条。
- 历史只读或缺失规划记录时，聊天结果入口与写作工作台入口都停止跳转并说明原因，不再回退打开另一份规划。

## 追加修复：历史规划任务误开其他规划

`backend/moyu_agent_planning.py` 的 `public_session` 对从备份恢复的历史只读任务明确返回 `restored_read_only=true`、`planning_workflow=null`、`checkpoint_id=""`、`source_stale=true`。旧实现在聊天结果入口把 `authorPlanningSelected` 置空后进入创作规划页，而 `frontend/author-workspace.js` 的 `authorLoadPlanning` 在找不到指定规划时会回退到 `rows[0]`，因此点击历史规划任务可能打开另一份规划。写作工作台的“打开规划建立章节”入口有同样的选中逻辑。

修复内容：

- `frontend/agent-chat.js` 的结果入口在缺少 `planning_workflow.id` 或任务为历史只读时抛出明确提示并停止跳转，不再进入创作规划页；历史任务与普通缺失规划记录分别提示，不把数据缺失误标为历史任务。
- `frontend/author-workspace.js` 的写作工作台入口只在存在 `planning_workflow.id` 时显示“打开规划建立章节”，点击时再次核对；`authorLoadPlanning` 在指定的规划记录找不到时不再静默回退到最新规划，而是显示“未自动打开其他规划”，由作者显式选择查看当前最新规划。
- 卡片内补充“历史任务没有保留对应的创作规划/本次任务的规划记录缺失，原规划无法打开”的说明，结果按钮显示为“查看任务记录”；不伪造、不补猜原规划内容。
- 新增真实形状回归：先通过真实接口建立另一份规划，再分别用 `restored_read_only`、`planning_workflow=null`、空检查点的历史任务，以及非历史但缺少规划记录的任务点击结果按钮；断言仍停留在聊天、未选中其他规划、未产生 confirm/apply 写入。

## 追加回归：回应丢失、候选变化与场景标题

- 规划确认与采用在“服务已处理、浏览器收到失败”的情况下只写入一次：模拟 POST 被中断并让模拟任务前进，断言轮询、刷新和切换会话后 confirm/apply 各自只有 1 次写入，不会重复计费或重复推进。
- 操作前重新读取发现候选哈希变化时放弃确认：页面显示“规划阶段或候选已变化”，confirm 写入 0 次；刷新恢复后只确认 1 次。
- 场景候选预览显示所属分卷与章节标题，作者可在聊天内核对候选归属。
- 远程检查超时：提交 `3228ee1` 的 GitHub Actions 在 25 分钟作业上限处被取消（当时 Contract fixtures 步骤比成功运行慢约 3 分钟，不是测试失败）；`.github/workflows/ci.yml` 的 `timeout-minutes` 已从 25 调整为 35，并在后续推送后重新运行核对，最终以 GitHub Actions 结果为准。
