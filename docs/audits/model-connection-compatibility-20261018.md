# 模型连接兼容修复验收

日期：2026-10-18。

## 改动范围

参考 [NovelForge 的模型配置表单](https://github.com/RhythmicWave/NovelForge/blob/a485814411546b3980df0a1696a0fb6a043d56ce/frontend/src/renderer/src/components/setting/LLMConfigForm.vue)，增加模型列表查询和折叠的兼容设置。流程保持“填写连接 → 测试 → 保存模型 → 分配用途”。本次仍使用兼容的聊天接口，没有增加其他原生协议。

- 基础地址与完整 `/chat/completions` 地址均可使用。
- 模型列表查询不保存草稿、不创建生成任务，不跟随重定向；列表不可用时仍能手动填写。
- 输出长度字段与流式用量开关随连接保存，贯穿用途任务、重试以及继承和独立配置的写作总管。
- 修改地址、密钥、模型或兼容项后，原测试结果失效。迟到的列表不会覆盖其他连接、作品或页面。
- 网络失败、名称不一致、名称未回传分别显示。名称不一致时“使用回传名称”只填写草稿，必须重新测试。
- 回复完整但未回传名称的连接可保存，模型库和用途设置持续提示名称未核实。名称相同也不能证明服务底层实际运行的模型身份。

## 经授权的真实连接测试

使用作者允许的本地测试凭据查询模型列表，返回 28 个名称。两次明确发起的连接测试没有自动重试：

1. 请求 `deepseek-v4.1-flash-1017`，完整回复回传名称为 `deepseek-v4.1-flash`，正确拒绝保存名称不一致的连接。
2. 请求 `deepseek-v4.1-flash`，回复完整且回传名称相同，测试通过并在临时数据库成功保存。

这些结果不能确定原截图中断线的具体原因，也不能证明底层模型身份。服务返回的用量分项与总量矛盾，计费状态继续标为未知。真实密钥未写入源码、文档或截图，真实测试的临时数据库和凭据目录已清理。
