# 相邻用户消息合并诊断 v1

方案日期：2026-10-14，Asia/Shanghai。本协议在发送前离线保存；是否已经冻结或执行，以同目录`plan.json`、`preparation-evidence.json`、请求账本和样本为准。`prepare`成功后以冻结方案、完整请求正文、历史账本及来源指纹为执行依据。冻结后不得改写原件或重复身份。

## 目的与唯一变量

待检验假设：同一整理输入将两个相邻`user`消息合为一个，是否改变“请求关闭思考却返回非空思考字段及1字正文”的表现。`user`就是用户提交给模型的文字消息。本次只改变相邻用户消息的边界，保留三条消息全部原文字节及其顺序。

第一条`system`消息原字节保留；后两条`user`消息以固定两个LF换行连接，即`\n\n`、UTF-8十六进制`0a0a`、内容增加2字节。LF就是普通换行符。JSON请求中两个换行以`\n\n`编码，占4字节；移除29字节消息对象边界，整份请求从7367字节变为7342字节，净少25字节。最后的完整候选JSON仍是合并消息的逐字后缀，不能解析后另行重排、缩短、删事实或改作者要求。

保持`glm-5.1`、温度0.65、`thinking.type=disabled`、3000`max_tokens`、`stream=false`及纯正文回复格式。温度是模型生成时的变化幅度；本轮不改它。`max_tokens`是模型输出用量上限，不能当作正文字数。两次新请求之间正文完全相同，第二次只使用新的独立身份核查一次重复稳定性，不把第一份新回复当作新父稿。

不缩短系统要求、不改候选事实、不换模型、不增加输出预算、不另加`reasoning_effort`、`clear_thinking`或随机种子。非流式表示一次完整JSON回复。原非流式1字失败只作历史参照，不重新调用未合并输入，不构成新的配对文学对照或新增独立故事。

## 已有证据与范围

本方案来自`literary-revision-v1`的墨屿整理请求及`literary-transport-v1`已失败的非流式请求。前者流式，后者非流式，两种模式都只生成“铁”1字并观察到非空`reasoning_content`。旁路读取与产品正文相同，因此不能以仅流式正文丢失作为已证实解释，不能把思考字段拼进正文。

原候选868个非空白字符完整保留。冻结验收仍为600至850个非空白字符，标点、数字和字母计入；目标约720。原稿事实优先于候选：钥匙原藏林岚左靴内侧，涨潮固定22点10分，林岚不知道陆衡凶手，手机没有信号。原稿收信在陆衡死后第三天，候选所写第二天不能成为已确认事实；已有当前原稿21点56分的时序也优先于候选。

这是同一原候选的探索协议诊断，新增独立故事数0、文学盲评数0，不做基线与墨屿效果比较。`stop`按实际协议保留，不能因输出tokens恰为3000而伪造为`length`。工程验证、机械合格或两次结果相同都不等于文学改善或第一梯队。

## 费用与累计门

每次执行前重新读取所有历史文学账本及独立协议诊断，不依赖手填累计数字。冻结起点必须同时满足34条请求预留、63876个可信完整tokens、63876已知用量下界、10条缺完整用量。金额未知；缺用量不表示免费，预留也不证明已收费。

原累计60次请求、180000个已知tokens的停止阈值保持不变，不能通过换目录归零。本轮最多两次新增预留，阶段一最多1次；阶段一任何失败立即停止。只有全部机械检查和独立事实核查均合格，才能以相同body和新身份追加最多1次非流式稳定性请求。

起点剩余26条请求、116124个已知tokens，不是金额上限或本轮调用额度。本轮预算是至多两次；不因失败、网络错误、缺用量或成功继续扩题，不执行付费评审，不自动重试。未知收费或收到响应后本机保存失败也不能重发。

## 免费预检查与冻结

`preview`和`self-check`只读取无密钥配置、历史证据和本地样例，不读取凭据，不调用接口、不预留费用。免费fixture使用模拟回复核对：

1. 只合并相邻用户消息，系统原字节、故事资料原字节与完整候选JSON后缀均一致；合并前后的非消息参数相同。
2. 累计账本实际重算，冻结全部历史账本指纹；旧失败身份不重放。执行器、提供方、输出契约模块、评测模块及本协议也冻结指纹。
3. 独立旁路只观察同一次已解码响应，不发送第二条“核对请求”。它全程累计正文、`reasoning_content`和`reasoning`两种思考字段、拒绝、结束原因、模式和用量形状，仅保存字段名、类型、计数、字符长度及正文，不保存思考文字。非空文字及非null、非字符串的异常思考形状分别计数并阻断。
4. 字段形状日志可截为开头112和末尾16条，但全程统计不截断。空白思考字段记录长度却不算非空；任何非空思考字段均阻断。
5. 冻结文档、完整请求或来源变化、旧阶段已经预留、第一阶段无事实核查，均在读取运行密钥和发请求前停止。

`prepare`保存`plan.json`、`frozen-request.json`、`frozen-request.body.json`、`preparation-evidence.json`，不会发送请求、读取密钥或建立预留。最终执行才从运行环境读取`MOYU_AI_API_KEY`，不会保存密钥或请求头。命令参数不接收明文密钥。

## 第一阶段机械闸门

第一阶段仅发送合并后的固定非流式请求一次。出现以下任一情况，立即停止，不执行稳定性阶段，不重试、不改提示或送盲评：

1. HTTP不是200、网络失败、超时、无完整返回、响应不是JSON、模型名缺失或不同、提供方错误、拒绝、正文为空，或同一次调用出现多次外部发送。
2. 结束值不是实际`stop`，完成不是`complete`，实际截断、未知状态；不能改写传输元数据来使结果通过。
3. 任意非空`reasoning_content`或`reasoning`，思考字段含非null、非字符串的异常形状，正文旁路与产品解析不一致、全程摘要不同，或响应形状不能完整解释。思考文字不能作为正文；未知形状不声称已经读到非空思考内容。
4. 用量缺失、不完整、算术冲突，旁路原数字与产品用量不一致，或者累计门已达到。未知部分和缺用量继续入账。
5. 正文长度不在600至850，出现分析/解释污染，或输出契约验收失败。不截短、不补齐、不缩窄字数门。

成功结束只表示传输完成。产品的`safe_to_apply=true`仍不能替代本诊断的机械闸门；本轮另记独立检查结果。

## 独立事实核查与第二阶段

第一阶段机械合格后，审阅完整候选及原资料；没有审阅或原文太短无法判断，不能写“零事实违规”。核查必须逐项提供本候选原文引用、理由和通过/失败：

1. 已确认事实保持，钥匙地点、涨潮时间、认知及无信号状态无冲突。
2. 原稿优先，候选中新造或冲突信息不被当作已确认事实，尤其收信日期与已知时序。
3. 全程限林岚视角，没有直接知道凶手或其他人物内心。
4. 林岚在22点10分涨潮前离开仓库，有明确事件依据。
5. 旧码头和左靴内侧月牙钥匙推动实际选择及行动。
6. 保留完整场景、关键事件、行动直接结果及结尾，不以分析或字数报告替代正文。

`review-first --review-file`只保存一次独立核查，绑定第一阶段完整记录和正文指纹；检查项缺失、引用不在本候选内、只写通过无依据时拒绝保存。失败核查保留，不能改写为合格再放开第二阶段。

只有第一阶段机械和事实全部合格，`second`才许可再发同body一次；第二阶段使用独立请求身份、非流式、同模型和同预算。第一阶段“通过”不能假定第二阶段也通过，第二阶段仍逐项检查并独立报告，最多两次结束，不扩大文学范围。

## 允许的结论

合并后仍出现非空思考字段或1字正文，只能报告“消息边界变化未消除本次异常”。合并后合格，可以报告固定输入这次通过协议、字数和事实门，但旧结果与新结果相隔且温度不为0，不能确认消息合并是根因修复。两次都合格，也只能报告本固定输入的两次观察，不能声称稳定关闭思考、文学质量提升、作者效率或第一梯队。

调用命令：先离线`preview`及免费fixture，通过审查后`prepare`；`first`执行阶段一。只有阶段一合格并保存`review-first`结果后才执行`second`。命令和输出不能含真实密钥；无密钥时执行器在预留前停止。
