# storyforge 专责审查：对墨屿的差距与实施建议

审查日期：2026-10-13（北京时间）。只读审查，没有修改产品源码、真实手稿、配置、发布状态或调用收费模型。

## 结论

StoryForge 值得列入“工程能力第一梯队候选”，理由是可追到作者入口的长篇组织、选区候选、版本防覆盖、章后记忆、上下文注册和导入生命周期。不能据此宣称真实模型写作品质领先，也不能据大量测试文件宣称所有页面和生产服务已通过本次验证。

墨屿最需要补的不是多几个 AI 按钮，而是“作品身份 → 冻结写作范围 → 候选确认 → 版本条件保存 → 失效传播 → 后续检索”的完整作者链。现有后台已有范围补丁、运行队列、取消和续读流，但当前页面大多尚未连接；多书、卷和结构化场景尚不能供作者完整使用。

本次发现一个已隔离复现的 P1：在甲章发起生成，等待时切换乙章，甲章响应重新建立全局候选，采纳会改写浏览器内乙章。入口层清空候选没有处理正在进行的请求。根代理随后在真实页面复核：页面发生错章采纳，但数据库因版本冲突拒绝保存；不能报告“错章正文已持久化”。

## 已复现的缺陷与边界

### P1：生成过程中切换章节会采纳到错误章节

- 来源：固定基线的 `app.js:71`、`app.js:73`、`app.js:226`，当前修复后的行号不沿用。
- 触发：甲章生成请求已发出 → 点击乙章（会清空当前候选）→ 甲章响应到达（全局 aiDraft 被重新赋值）→ 采纳调用当前 `chapter()`。
- R 范围：本专责是真实函数隔离实验，模拟延迟响应，没有真实模型/浏览器完整验收。候选里即使保存甲章的 context，采纳也没有使用它核对目标。根代理补充真实页面验证：本地发生错章采纳，数据库返回版本冲突、未保存；页面实测原始证据由主报告汇总。不能把“本地误写”扩大为“数据库已持久化误写”。
- 修复方向：每个候选冻结作品、分支、章节、基准正文版本和文本摘要值；响应只回到所属章节；采纳调用后台补丁/提交接口，由保存层再次检查版本。冻结本身解决章归属，保存条件解决作者后写的内容被旧结果覆盖。
- 借鉴：上游 `FloatingToolbar.tsx:179-183`与 `selection-edit-durable.ts:863-878`。

### 新书函数覆盖实验不列正常入口缺陷

`app.js:250`在已有稿件下执行会改写原书，但 `app.js:135-136,218`将普通入口限制在新项目。本次主动核查反例后降级为“多书扩展前必须保护”，没有把函数实验夸大为当前常见用户路径。父报告应保留这一限定。

适合借鉴：

1. 三个小型登记中心：可读材料、可正式写字段、需随完整备份保存的数据。上游 `src/lib/registry/assemble-context.ts:137`、`adopt.ts:63`、`registry-export.ts:505`分别对应，能避免越做越多却有孤立入口。
2. 候选包含冻结范围、源版本、正式写入意图及检查结果；正文变更同步使摘要和证据过期。
3. 章后的摘要与下一章交接一起生成并保存，后续上下文真正消费。上游 `src/lib/ai/chapter-memory/run-chapter-memory.ts:18-79`提供核心样板。
4. 运行契约与预算在程序中验证，失败/未知响应窗口不静默重发；分清文档、代码、测试和文学审阅。

不宜照搬：

1. 不要直接移植 128 张浏览器表或完整多叙事产品架构。墨屿当前优先服务长篇作者，世界游戏、漫画、跑团和社区会分散主路径。
2. 不要用浏览器本地保存替代墨屿现有 SQLite（本机数据库）。上游 IndexedDB 主数据与同库快照仍会受清理浏览器数据影响；墨屿应保持独立完整备份优势。
3. 不照抄 `src/lib/ai/client.ts:168-207`的厂商例外或模型名推断；这类接口规则会变化，应靠实际能力探测和带固定响应样本的兼容测试。
4. 不照抄上游将“记住密钥”存 localStorage 的路径 `src/stores/ai-config.ts:267-276`；墨屿当前服务端环境配置更适合避免手稿导出混入密钥，新增界面配置时继续隔离凭据。
5. 不把规则审稿、统计区间、上游百万字符声明当作真实文学质量认证，也不把“发送取消”当作已停止上游计费。

## 第一梯队验收裁决

| 能力闸门 | StoryForge 本次裁决 | 墨屿本次裁决 |
|---|---|---|
| 作者入口到保存到后续使用 | 主要长篇入口 E，纯统计组件 R；完整页面 U。 | 单书写作/故事结构 E，范围补丁 R-接口；候选错章 R-组件失败。 |
| 作品隔离、候选版本条件写入 | 工作区身份、范围及选区双哈希链 E；未做浏览器隔离反例 U。 | 后台已有 revision/branch head E；页面候选冻结不足，不能通过。 |
| 长期记忆、证据及失效 | 分块/摘要哈希、正式写入失效传播、来源装配 E。 | 确认记忆、来源和知识范围 E；自动章后工作流未完整接通。 |
| 可恢复、可停止、透明费用 | 持久候选及运行、预算、用量 E；完整现场 U。 | 后台相关功能 E；作者页缺进度/停止，完整页面备份范围不足。 |
| 实际模型文学质量与持续运行 | U；不能授予最终文学质量领先结论。 | U；离线模板及规则通过不能代替模型验收。 |

因此：StoryForge 是墨屿长篇工程改造的重点参考，但“第一梯队最终验收”仍需两项目的真实页面、隔离数据恢复、兼容响应测试及获授权的真实模型盲审。墨屿当前应先过候选写入安全闸门，再考虑更丰富的创作自动化。
