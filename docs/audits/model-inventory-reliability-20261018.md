# 模型清单连接与暂停恢复验收

日期：2026-10-18。范围：新增模型时自动获取清单、网络错误提示，以及清单获取期间测试连接的恢复行为。

## 现场结论

截图中的“获取模型列表时连接中断”来自后台模型清单请求。原实现把证书校验、加密握手、域名解析及连接重置等错误统一包装成同一提示，不能根据截图确定当时是哪一种错误。

使用与本机预览相同的 Python 3.11 解释器、作者之前授权的本地测试凭据，实际请求 `https://api.icodexs.com/v1/models`，返回 HTTP 200 和28个模型。加密连接使用 TLS 1.3。本次实际请求未复现原截图的连接中断，因此不能认定故障一定来自证书、代理、密钥或地址。

另独立复现了一个界面缺陷：清单尚在获取时点击“测试连接”，会取消清单请求，但保留“已经获取过”的标记；测试结束后不再获取，提示可能一直停留在获取中。

## 修复

- 模型清单连接错误分别提示证书校验、加密握手、域名解析、拒绝连接、提前断开和超时。保留通用中断错误，所有提示使用固定安全文字，不回传原始异常或密钥。
- 仅在模型清单 GET 尚未取得 HTTP 响应、发生连接重置或加密连接意外结束时，允许重新连接一次。两次共享原总时限，连接超时受剩余时间约束。
- 证书错误、域名解析错误、HTTP 鉴权或限流、重定向、格式错误及响应正文中断均不自动重试。生成 POST 的行为没有改变，也不增加付费请求重试。
- 实际经过时间与计时器事件共同检查超时，避免计时器线程调度稍晚时误报，或超过预算后继续发送清单请求。
- 清单获取中被临时暂停后，恢复启用时重新获取。成功与失败的尝试记录仍保留，避免重复查询或失败循环；旧清单仍不能覆盖新配置。

3. 明确发起一次连接测试，回复完整且回传名称相同。
4. 保存模型并设为默认，模型库中出现一个已验证连接，用途默认选择一致。
5. 保存没有再次调用模型；界面密钥输入已清空，页面错误为0。

共发起一次清单查询、一次真实连接测试和一次本机保存。该流程没有读取作者作品，临时数据库与凭据目录已在结束后清理。密钥未写入源码、报告或截图。此验证只证明该次接口可调用，不证明服务底层模型身份或文学质量。
