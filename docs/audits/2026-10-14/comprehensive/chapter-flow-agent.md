# 写作总管与连续章节创作

日期：2026-10-16，上海时间。仅限单人本机电脑创作，不包含手机端。

本批把主页面持续聊天接入本章归档与下一章准备，继续沿用现有写作总管、正文候选、章后记忆和故事审稿。实现与验证分开登记；本文件中的专项结果不代替完整整轮、实际预览和对应提交的GitHub检查。

## 作者流程

| 作者操作 | 系统实际处理 | 保留的确认 |
| --- | --- | --- |
| 在聊天中要求写完本章、进入下一章 | 总管提出固定名称“完成本章，打开下一章”的建议 | 作者确认此步骤才执行 |
| 确认进入下一章 | 核对正文与资料版本、本章任务、待决定记忆、审稿和目录，依次完成三阶段归档 | 仍须先处理待决定记忆和阻断问题，不绕过作者判断 |
| 打开后续章 | 复用目录中紧邻下一章，保留已有正文、规划、视角和其他任务字段 | 没有后续章时建立空白草稿，仅继承视角，不自动生成正文 |
| 承接上章 | 从“本章任务与回顾”打开可编辑表单，空目标可带入上章交接，空视角可带入上章视角 | 作者编辑并确认目标、场景和视角；场景不自动编造，已有内容不自动覆盖 |
| 查看旧聊天的任务结果 | 直接读取该条建议关联的任务，在当前正文下方显示 | 可返回本章全部任务，不因只展示最近三条而丢失目标 |
| 恢复中断的确认 | 查找同一建议已经建立的任务，校对作品、分支、章节、要求、类型和只读状态，再恢复关联 | 只找回原任务，不启动任务、不新增调用；尚未建立任务时仍按当前稿件重新校验 |

本章归档和建立下一章共用一次事务，即一组操作要么全部保存，要么全部撤回。任一步检查或写入失败不会留下“本章已经完成、下一章却没有建立”的半成状态。重复确认、并发点击和已保存回应丢失均返回同一后续章与归档记录。

尚未接入正文目录的下一章规划不会被静默替换为空白章；作者须先在创作规划中建立对应章节。没有把本批功能描述为全书自主创作、自动建书或自动确认正式事实。

## 来源与备份

下一章建议绑定作品、分支、正文版本和指纹、本章任务卡、目录顺序、蓝图、记忆、审稿及既有归档。相关内容发生变化时，旧建议拒绝执行，原稿与建议保留。聊天入队等不改变写作材料的事件不会使建议误判过期。

上章承接预览不写作品。确认保存核对当前章、紧邻前章、正文、任务、目录关系以及作品和分支状态；来源变化返回冲突。归档作品、封存分支、完稿书和已完成本章不能借此写入任务字段。

完整ZIP包含新动作及其后续章和归档来源；恢复副本重映射章节、正文版本和归档记录编号。历史聊天与任务仍只读，密钥和本机连接不进入备份。
