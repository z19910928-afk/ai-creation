# 有版本的可复用作者写法：B2 最小实现规格

本文是 B2 的只读设计和验收合同，不代表功能已经实现、真实服务已经迁移或文学效果已经通过。范围是电脑端编辑器的九种写作用途：续写、润色、大纲、场景、总结、检查、灵感、章节分析和语义审稿。规划向导没有明确选择时，不自动套用任何作者写法。

## 现有边界

当前项目已经有作品级的文风和写作要求，也有一次性补充要求、提示预览、持久任务、候选版本和完整 ZIP 备份：

- [moyu_settings.py](../../../../moyu_settings.py) 保存全局 `styles.tone` 与 `styles.instructions`。
- [moyu_context.py](../../../../moyu_context.py) 会把一次性要求用于材料召回，并以 UTF-8 预算保留任务要求。
- [server.py](../../../../server.py) 构造系统提示、用户提示、输出契约和持久队列；队列记录会冻结 provider 请求审计。
- [moyu_output.py](../../../../moyu_output.py) 只机械检查正文长度和明显的规划元话语，不判断文学质量。
- [moyu_backups.py](../../../../moyu_backups.py) 对完整项目 ZIP 做闭合图、字段白名单和恢复前只读校验。
- [app.js](../../../../app.js) 保存编辑器中的一次性要求草稿并捕获生成请求快照；[author-workspace.js](../../../../author-workspace.js) 提供电脑端编辑器、章后分析和故事审稿入口。

B2 应在这些边界上增加一个独立的作者写法层。它不能替换系统任务、材料来源、证据约束、输出模式、模型参数或一次性任务快照，也不能把模板库做成可编辑的系统角色。

## 最小数据合同

新增 `moyu_author_styles.py`，集中负责表结构、校验、变量解析、渲染、版本追加、复制和公开投影。服务端只调用这个模块，不在 HTTP 分支里重复解析规则。沿用标准库、SQLite 和现有 HTTP 服务，不新增模板引擎或框架。

选定两张作品级附加表：

```text
app_author_style
  id TEXT PRIMARY KEY
  project_id TEXT NOT NULL REFERENCES project(id)
  created_at TEXT NOT NULL
  UNIQUE(id, project_id)

app_author_style_version
  id TEXT PRIMARY KEY
  style_id TEXT NOT NULL
  project_id TEXT NOT NULL REFERENCES project(id)
  version INTEGER NOT NULL CHECK(version >= 1)
  name TEXT NOT NULL
  task_ids_json TEXT NOT NULL
  template TEXT NOT NULL
  variables_json TEXT NOT NULL
  archived INTEGER NOT NULL DEFAULT 0 CHECK(archived IN (0,1))
  content_sha256 TEXT NOT NULL
  request_id TEXT NOT NULL
  request_hash TEXT NOT NULL
  created_at TEXT NOT NULL
  UNIQUE(style_id, version)
  UNIQUE(project_id, request_id)
  FOREIGN KEY(style_id, project_id) REFERENCES app_author_style(id, project_id)
```

`app_author_style` 只保存身份、作品归属和创建时间，不保存 `current_version_id` 或可变归档状态。当前版本按该写法的最大 `version` 读取，避免与版本表形成外键环。版本行一旦写入不得更新、删除或覆盖，需有数据库级 UPDATE、DELETE 和覆盖插入保护。归档或取消归档也追加完整版本，只改变该版本的 `archived` 开关，保留全部旧版本。回退复制目标版本的完整内容成为新序号，包括目标版本的归档开关。

版本的规范化内容包括 `name`、按稳定顺序排列的 `task_ids`、模板原文、解析得到的变量名数组和 `archived`，不包括数据库 ID、时间、请求 ID 或运行时变量值。`content_sha256` 对规范化 UTF-8 JSON 计算。新 `request_id` 的保存、改名、修改、回退、归档和取消归档均追加完整版本，包括作者再次明确保存相同内容的情况；只有重复同一次请求不追加。不能给内容哈希加唯一约束，否则回退到历史内容会失败。

版本行保存 `request_id` 和规范化 `request_hash`，同作品下请求 ID 唯一；重复请求先查既有版本并比较请求哈希，再检查当前最新版本。请求哈希包括操作、请求作用域、写法/来源版本、完整提交内容、`expected_version` 和复制目标，不能只比较模板正文。失败请求不留下版本或成功事件。

变量只允许有限的文本占位符：

- 模板占位符固定为 `{{名字}}`，变量名由 ASCII 字母、数字、下划线及汉字组成，最多 40 个 Unicode 字符。按原名精确匹配，大小写不合并，不偷偷修剪空格。
- 从模板按首次出现顺序提取最多 20 个不同变量名；同名多次出现使用同一个值。`variables_json` 由解析器派生为名字数组，作者无需配置技术声明，也不能提交与模板不一致的自定义声明。
- UI 根据名字数组生成必填输入框，例如 `{{视角}}`、`{{节奏}}`；不增加默认值、过滤器、函数、路径、嵌套占位符或表达式。
- 变量值按原文字面替换。美元符号、反斜线、`$&`、`$1`、花括号、换行和 Unicode 不得触发第二次展开。
- 所有提取变量都为必填，不提供隐式空值。模板的 `{{` 和 `}}` 是保留分隔符，未配对、空占位、嵌套或表达式均拒绝；缺值、空白值、未知变量、非文字值及用途不适配均在渲染前拒绝。单个花括号和 `${x}` 是普通文字；变量值内的 `{{other}}` 也仍是普通文字，不再解析。
- 名称最多 120 个 Unicode 字符且最多 480 字节；模板最多 8,000 个 Unicode 字符且最多 32,000 字节；单个变量值最多 2,000 个 Unicode 字符且最多 8,000 字节；渲染后的写法最多 12,000 个 Unicode 字符且最多 48,000 字节。字节边界采用严格 UTF-8 编码；字符边界不能按浏览器 UTF-16 单元误裁 emoji。

渲染先解析模板原始占位符范围，再以片段拼接或返回字面值的回调进行一次替换。不得使用表达式求值、`str.format`、会解释替换字符串的正则接口或递归展开。新增空模板、名称为空、用途数组为空/重复/未知也在保存前拒绝，所有原文字段保留，不用静默裁剪替代报错。

复制必须明确传入 `target_project_id`，在当前来源作品内读取固定来源版本，并检查目标作品存在、属于当前本机可操作作品且未归档；支持明确复制到本书或另一书。目标创建新的 `style_id`、版本 ID 和第 1 版，复制文字与用途，初始 `archived=false`。不能共享可变 ID、覆盖目标现有写法或改写目标正在编辑的一次性要求草稿。

跨目标复制复用已有不可变 `event_log`：在来源作品下，以该 `request_id` 登记请求哈希和目标回执，与目标版本同一事务写入。重复请求先读此回执，改目标或来源版本的同一请求返回 409。版本仍使用 `UNIQUE(project_id, request_id)`，不用全库请求 ID 唯一，否则完整 ZIP 恢复成同库独立副本时会与原历史请求冲突。版本列表和幂等响应的归属核验不能泄露其他作品内容。

## 渲染和提示合同

一次任务的作者要求分三层，优先级从低到高是：

1. 现有作品级默认文风和写作要求；
2. 作者明确选择的写法版本及其渲染结果；
3. 本次任务输入框中的一次性要求。

系统任务合同和材料、来源、证据、输出格式、JSON 模式、配额、模型安全规则始终高于这三层。一次性要求可以覆盖写法中相互冲突的节奏、叙述距离或动作偏好，但不能越过系统合同，也不能解除材料来源检查。

服务端在创建预览或任务时必须：

1. 按当前作品、用途、固定 `style_id` 和固定 `version_id` 查出版本；
2. 重新解析模板，核对派生变量数组和本次变量值；
3. 用单次、无表达式的字面渲染得到 `rendered_style`；
4. 保留现有全局要求的发送位置，以稳定分隔符按“渲染写法、一次性要求”顺序构造 `merged_author_instruction`；明确告诉模型一次性要求优先；
5. 用分层的合并要求计算本次 `output_contract`，确定性选择一次性要求的明确长度，否则选择写法中的明确长度。现有全局要求维持其原提示行为，不在 B2 新增全局字数解析。应复用现有解析器分别解析两段，选择优先层的完整长度对象，不能把冲突文字直接拼接后交给只取首个范围的解析器；
6. 把写法绑定、渲染文字、合并要求及其哈希写入请求审计和任务同意记录。

例如写法要求 800 至 1,000 字，本次要求“不超过600字”，有效长度是“不超过600字”，不能保留写法的 800 字下限。模板无长度、本次无长度时，继续使用现有未指定长度合同，不新增猜测。两段中任意明确长度的格式非法，都先给出该段的校验错误。

对润色任务，百分比或范围长度的基准仍是冻结的选中原句，不能因为写法增加了文字要求而改成整章基准。输出契约通过只说明机械字数和明显规划标记，不代表文学质量通过。

写法文字计入 UTF-8 预算。当前 `moyu_context.py` 以 `1800 + len(instruction.encode("utf-8"))` 保留要求空间；B2 应加一个默认值为零的 `additional_instruction_utf8_bytes`，以渲染写法及新增标题、分隔符和实际系统长度约束的字节数增加预留，并同步覆盖 `server.ai_context` 的规划二次预算路径。冻结的 `_author_style` 元数据在完成预算后附加，不再作为模型材料重复计数。最终预览登记实际消息 UTF-8 字节数，保留“估算而非精确 tokens”的标记；新增层不能靠原有固定 1,800 字节额度兜底。预算不足时先返回可解释的 400，不能静默删掉写法，也不能让写法占用材料后再把当前正文或必需证据截掉。

渲染写法是作者要求，不是事实、人物认知、设定或参考原句。它不进入材料召回关键词和 BM25 权重；检索仍只使用一次性要求及当前任务已有的章节、计划和正文查询词。相同查询输入的检索 `query_hash`、相关性评分及预算裁减前排序保持不变；写法占用预算可能减少可选召回材料，但必须记录裁减，不能改变引用边界、当前正文或必需证据。

## 任务冻结和规划边界

编辑器先支持九种用途的明确手选。选择器、变量表单和版本管理使用现有电脑端 modal 和表单风格；不增加手机端布局要求。选择或变量变化后，旧预览立即失效，不能在异步完成后重新读取当前选择器来拼请求。

`aiRequestSnapshot` 应捕获以下不可变值：

```text
project_id, branch_id, chapter_id, sequence
style_id, style_version_id, style_version, style_content_sha256
declared_variables, supplied_variables, variables_sha256
rendered_style, rendered_style_sha256
merged_author_instruction, merged_instruction_sha256
source_revision_id, source_body_hash, reference selections
```

服务端收到的选择只包含 `style_id`、`version_id` 和变量值，版本正文、派生变量、渲染结果和哈希均由服务端重读并计算；不能信任浏览器提交的渲染正文。`context._author_style` 和 `consent.author_style` 保存一致的固定绑定，公开任务只展示名称、序号、版本 ID 和内容哈希；需要回看时另读当前作品下的历史版本。原请求、正文和变量仍留在本机，不增加公开任务列表的正文泄露面。

队列、直接生成、重试和候选整理都只消费这个快照。写法后来新增版本、归档、变量表单改变或作品切换，都不能改写已保存任务的 provider 请求、模型、采样、输出上限、正文来源或计费记录。未知完成/计费状态仍沿用现有 409 拒绝规则，不能借新版写法自动重发。

首次建任务时核对固定版本存在、属于当前作品、适用于当前用途；固定版本和当前头版本都须未归档，防止选择旧的未归档版本绕过目前的归档决定。后续派发、重试、整理按已保存版本和完整请求核对一致性，不追踪写法最新版本或归档状态；新增版本和后续归档不会使旧任务材料凭据失效。原稿和实际消费资料改变时仍沿用原有阻断规则。旧无 `_author_style`、无 `author_style` 的任务完全保留原路径；部分绑定缺失或哈希损坏的新任务必须在发送前拒绝。

规划向导第一版不自动读取编辑器当前选择，也不读取作品级“最近使用”写法。没有明确 `author_style` 绑定时，规划任务的提示完全保持现有行为；以后若给规划页面增加选择器，也必须把固定版本和变量显式送入同一快照合同。

## 保存、并发、去重和复制

创建带 `request_id`，`expected_version` 固定为 0；编辑、回退、归档、取消归档带 `request_id` 和当前 `expected_version`；复制带 `request_id`、固定来源版本及明确目标。所有修改在 `BEGIN IMMEDIATE` 中完成校验和写入：

- `expected_version` 不是当前最大版本时返回 409，数据库和密钥文件均不改变。
- 相同 `request_id` 与相同规范化内容重复提交，返回第一次的版本和 `idempotent: true`。
- 相同 `request_id` 但内容不同，返回 409，不能覆盖第一次结果。
- 新请求追加下一个整数版本，保留明确保存或回退的操作；同一次请求无论当前头后来如何变化都读回第一次的版本，不再次追加。
- 旧版本始终可读、可预览、可复制，但不能直接修改。
- 归档和取消归档都追加完整版本；目前归档的写法不能用于新任务，历史任务、旧候选和备份恢复仍可追溯其版本内容。

版本列表、变量预览和跨书复制返回作品、分支、请求序列和版本绑定。浏览器收到迟到结果时，必须同时检查当前作品、分支、章节、序列号和表单仍在文档中；表单已卸载时丢弃结果，不覆盖新作品或新章节。

每个回执只表示这次写法保存或复制已经完成，不能授权模型请求。写法保存成功但后续页面读回失败时保留 `request_id`，按同一请求读回版本；不要更换请求 ID 盲目重存。目标复制成功、原页面丢失回复时，同一来源请求仍读回同一个目标写法；若目标已被后续操作归档，也不能为了返回当前状态再复制一份。

## 备份与实际服务迁移

新表按现有 `moyu_backups.py` 的附加表模式注册为 `KNOWN_ADDITIVE_TABLES`。旧完整 ZIP 没有作者写法表时，当前新服务应按空写法库兼容恢复；新 ZIP 恢复到旧服务时应明确返回“不支持新增表”的预览错误，且零写入。不能为了让旧报告“通过”而改写历史失败报告或把新表塞进旧 `REQUIRED_TABLES`。

恢复副本必须：

- 对两张新表的 ID、作品 ID、版本 ID 和 `style_id` 做完整重映射；
- 保留模板、派生变量数组、变量值、所有版本的归档开关、请求记录和 `content_sha256` 的原文字节；
- 不把变量值中看似 ID 的普通文字当作作品关系改写；
- 没有两张新表是合法旧包；仅缺一张、有写法却无第 1 版、版本不连续/重复、跨作品引用、派生变量与模板不一致或内容哈希不符在 preview 阶段拒绝；
- 不恢复密钥、不自动派发历史任务、不改变原作品。

旧 ZIP 省略两张表是合法兼容情况；新 ZIP 若有任一写法任务绑定却省略表或版本，必须拒绝，不能把有损新包当作旧包。恢复后版本行 `request_id` 仍隔离在新作品内；请求哈希作为历史审计保持原值，不拿它冒充基于新作品 ID 的新请求哈希。复制事件中指向未包含他书的目标回执只保留为历史文本，恢复副本不能用它读回或重新授权原目标的可变对象。新复制用新请求 ID 和明确目标，不自动继续恢复前的跨书操作。

实际服务增加表时必须单独执行一次“附加 schema”验收：新鲜空库和现有数据库都要检查表、列、唯一约束、不可变触发器、外键和 `PRAGMA foreign_key_check`；再用旧 ZIP、新 ZIP、坏 ZIP 各跑一次预览。该证据要登记实际服务源码 SHA、数据库 schema 表清单、迁移前后行数和零模型调用。不要把这次表迁移混入 B1 的旧整轮，也不要用旧失败记录的修改版替代新证据。若未来决定把基础 `SCHEMA_VERSION` 从 11 提升，必须同时实现旧版本 11 的只读兼容迁移并另起 release 标签；只增加附加表时沿用当前 additive-table 合同更稳妥。

## 最小 HTTP 和电脑端入口

服务端最小入口应包括：

- `GET /api/author-styles`：默认列当前作品的非归档写法和各自最新版本摘要；管理列表显式传 `include_archived=1` 以展示归档和取消归档入口；
- `GET /api/author-styles/{style_id}/versions`：列全部版本，包含哈希、适用用途、派生变量数组、归档状态和创建时间；
- `GET /api/author-styles/{style_id}/versions/{version_id}`：读取固定历史正文、用途及变量数组，避免模糊读取“当前版本”；
- `POST /api/author-styles`：创建第一版；
- `POST /api/author-styles/{style_id}/versions`：追加编辑或回退版本；
- `POST /api/author-styles/{style_id}/archive`：带明确开关归档或取消归档；
- `POST /api/author-styles/{style_id}/copy`：在明确目标作品后复制；
- `POST /api/author-styles/preview`：只校验和渲染未保存的编辑稿或明确固定版本，返回派生变量、渲染文字、内容/渲染哈希及字节数；无需章节、模型或密钥，真实库零写入、零发送，不作为模型任务授权；
- `POST /api/ai/prompt-preview` 与 `/api/ai/queue`：可选接收 `author_style` 绑定并返回冻结版本摘要。

独立写法预览明确区分未保存完整编辑稿与已保存固定版本，两种模式互斥，不允许前端用部分编辑正文覆盖服务端固定版本。它只展示写法本身；最终任务提示仍必须通过既有 `/api/ai/prompt-preview` 校验本次正文、用途、参考和合并要求。没有写法选择时，预览和任务请求不得添加空的伪绑定。旧客户端和旧任务不带 `author_style` 时继续完全按原路径执行。

编辑器在一次性要求输入框旁增加“作者写法”选择和管理入口。管理 modal 负责新建、命名、编辑、版本历史、回退、归档、变量预览和明确跨书复制；不把写法正文塞进全局作品草稿同步，不覆盖现有一次性要求输入。章节分析和语义审稿按钮也必须能明确选择写法或保持“未选择”，不能从最近一次续写任务偷带写法。

`summary` 与 `chapter_analysis`、`check` 与 `semantic_review` 在 B1 有参数别名，这不自动变成写法用途别名。B2 的适用用途按实际 task 精确匹配；同一写法想用于总结和章节分析时，作者需在用途多选中勾选两项。草稿旧格式缺写法字段时继续读回一次性要求；新草稿保存固定写法 ID、版本和变量值，丢失写法或归档时保留草稿并明确提示重新选择，不默选最近版本。

| `_check_graph` 的 `app_ai_job`/`ai_run` 分支、`_check_content` | 显式对照 context 与 consent 绑定、所属版本、派生变量、渲染/合并文字和 hash；核版本序列/作品归属 | 新部分绑定拒绝，旧无绑定兼容；已有任务原稿、参考和候选校验不绕过 |
| `JSON_REFERENCES`、`_check_json_graph`、`remap_value`、`transplant` | 在写法绑定的明确子树为 `style_id`、`version_id` 注册关系；变量值子树按验证过的纯文字保真 | 不全局劫持通用 `version_id` 键；名为 `project_id`、`chapter_id` 的用户变量不能被当作实体引用；模板、冻结 messages/payload、历史请求哈希不重写 |
| `_table_order`、`_insert_data`、隔离 scratch 校验 | 父表先于版本表，复合作品外键和触发器按实际 schema 验证 | 不形成头版本循环，restore 仍创建独立新作品、旧任务只读且不派发 |

版本内容哈希只绑定可复用文字和开关，不含作品 ID，因此恢复重映射不影响它。运行时变量哈希只绑定变量文字，渲染哈希和合并要求哈希只绑定发送文字。写法绑定中的实体 ID 则显式重映射；已有 `input_hash`、`request_sha256` 和冻结 payload 仍是原请求的历史证据，恢复副本继续使用现有只读标记，不能重新计算它们来把历史任务变成“可执行新任务”。

异常路径应明确区分：格式/缺变量/超预算 400；不存在或他书固定 ID 404；并发/重复 ID 不同内容/归档冲突 409；不可确定是否保存的网络问题只读回同一请求；未知模型完成/计费继续 409。复制必须先查目标作品，不能依靠 `ensure_seed` 自动创建用户没选过的目标。所有失败保留作者输入、原版本、原稿和已知用量，不自动重发模型。

## 验收合同

### 保存和变量

- 创建、编辑、回退都能读回新版本；旧版本内容、哈希和时间不变。
- 同一 `request_id` 重复请求只产生一个版本；不同内容的同一 `request_id` 返回 409；并发 `expected_version` 冲突全库原子回滚。
- 九种用途的适用范围、未知用途、未知变量、缺少必填值、派生变量不一致、长度超限和非法占位符均在 400 阻断。
- 变量值中的 `$&`、`$1`、反斜线、`${x}`、`{{other}}`、中文、换行和 Unicode 组合按字面保留；不执行表达式，不二次展开。模板原文的 `{{other}}` 则自动成为必填变量；未配对或表达式占位严格拒绝。
- 汉字/英文/数字/下划线名字、同名重复、20/21 个名字、名称 40/41 字符、值 2,000/2,001、模板 8,000/8,001、渲染 12,000/12,001 与 UTF-8 字节上限均有边界场景；父列复合作品归属、不可变 UPDATE/DELETE/REPLACE 也直接执行隔离数据库反例。
- 变量值不进入版本内容哈希；同一版本换变量值会生成不同的渲染哈希和不同的任务快照。

### 提示、预算和任务

- 预览显示的 provider body 与实际发送 body 字节一致，包含固定的写法版本、渲染变量和合并一次性要求。
- 一次性长度要求优先于写法长度要求；写法不含长度时保留一次性解析；两者均没有时不凭空生成长度合同。
- 写法 UTF-8 字节计入上下文预算，但不进入检索关键词、召回权重或作品事实。
- 修改或归档写法、切换作品/章节、改变变量或迟到事件都不能改写旧快照；重试、整理和规划旧任务继续使用原请求。
- 未选择写法的规划向导不自动套用任何写法；显式选择才产生绑定。
- 系统任务、JSON schema、来源指纹、人物认知边界、参考原句限制、输出上限、配额和未知计费保护始终有效。

### 备份和回归

- 旧无写法 ZIP 在新服务上预览和恢复成功，写法库为空且原数据不变。
- 新有写法 ZIP 能在新服务预览、确认恢复并保留所有版本和变量文字；密钥独立，旧任务只读。
- 新 ZIP 在旧服务上明确拒绝且零写入；坏版本、跨作品 ID、重复版本、哈希不符和变量结构坏包均在 preview 拒绝。
- 名字为 `project_id`、`chapter_id`、`style_id` 的变量，以及值恰好等于真实版本 ID 的变量在 ZIP 往返逐字保持；新版本/任务引用映射到独立副本，模板与冻结发送 payload 不变。
- 更新、回退、归档保存后丢回复的同请求读回、跨目标 copy 重复、改变 copy 目标和来源版本的冲突、恢复副本中历史 copy 回执不能授权原目标，都有全库原子场景。
- 新鲜空库、已有 B1 数据库和实际服务迁移后的 schema 都通过附加表、索引、触发器和外键核验。
- 直接生成、排队、重试、候选整理、章节分析和语义审稿至少各有一个真实本机 HTTP 场景；免费本机提供方调用与付费调用分开记账。
- 电脑端刷新、跨章、跨书、存储失败、保存后读回失败、版本冲突和异步迟到结果均有浏览器回归；本阶段不增加手机端验收。
- 管理页能列出归档写法并取消归档；空作品无章节时仍可新建写法、填写变量和只读预览，全部零模型调用。材料预览的预算、裁减和实际请求一致。

本合同只证明作者写法的保存、渲染、追溯和任务保护。它不能证明真实模型的文学质量、题材排名或“第一梯队”；文学评测仍需按路线图中的独立题材、双模型、双顺序和完整用量标准另行验收。

## 文件边界与交付顺序

最小源码范围是新增 `moyu_author_styles.py`；修改 `server.py` 的初始化、作品级端点、预览和任务创建、公开追溯；在 `moyu_context.py` 增加不影响召回的预算参数；在 `moyu_output.py` 增加分层长度选择 helper，保留原解析器和旧无写法行为；修改 `moyu_backups.py` 的两张附加表、显式引用、纯文字保护和内容校验；修改 `app.js` 的草稿、快照及当前性判定，修改 `author-workspace.js` 和 `styles.css` 的电脑选择与管理入口。`moyu_settings.py`、provider 库和九用途参数规则无需因 B2 改动。

先实现模块与隔离数据库合同，再接预览和真实本机发送，最后接电脑页面、备份往返和错误恢复。定向修前、修后报告分别绑定冻结来源；完整验收用新标签记录当前源码、附件指纹及费用，随后再核 GitHub 和实际服务。实际服务迁移前保存独立完整数据库备份，先确认待执行和正在执行的模型任务为零。迁移后按迁移前的全部既有表逐表比对内容和结构；允许的变化仅为登记在附加清单中的新表、索引和触发器，不能用总表数或总行数代替原稿与历史内容核对。
