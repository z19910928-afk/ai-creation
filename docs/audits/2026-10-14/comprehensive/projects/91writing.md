## 新复现与修复：临时创作要求离页丢失

本轮用真实 Chrome、1440×1000、新浏览器资料及冻结在内存的前端文件执行：

1. 进入章节写作，选择“润色所选文字”。
2. 填写合成要求“只改对白节奏，保留罗盘去向，不增加剧情。”
3. 去设定库查看资料，再返回章节写作。
4. 实际任务变为 `continue`，补充要求为空，页面没有脚本错误。

[修前浏览器证据](../evidence/91writing-moyu-instruction-draft-before-fix.json)保留文件指纹、动作、输入输出及访问范围。所有 API 刻意返回 503，外部地址被阻断；它验证的是电脑界面的发送前草稿，不证明后端丢任务，也没有费用。

源码原因：`authorEditorView()` 每次返回重新构建的 `<select id="aiTask">` 与无值的 `<input id="aiInstruction">`；`render()` 替换页面，现有缓存主要针对作品正文、候选、材料和规划，没有回填这两个输入。切页查看资料是正常作者流程，静默重置可导致下次生成任务不符合作者意图。

本轮已在 `app.js` 实现最小修复：

- `instructionDraftKey()` 用作品、分支、章节身份建立独立浏览器草稿。
- 输入和任务选择立即缓存；`render()`、`generateAI()` 和刷新前补存原控件值，重新绑定时回填。
- `cacheInstructionDraft()` 记住原控件身份；已卸载控件的迟到输入或清空不会改写其他草稿。
- 增加“清空要求”，清空本章补充要求并恢复续写，不影响其他章节或作品。
- 浏览器拒绝持久保存时明确提示并保留同页内存草稿；存储恢复后下一次缓存可自动补存，无需重新输入。
