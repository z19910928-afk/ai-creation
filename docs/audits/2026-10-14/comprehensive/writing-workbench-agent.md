# 电脑创作工作台与写作总管

日期：2026-10-16，上海时间。范围仅为单人本机电脑创作。

## 已实现的作者流程

本轮按[NovelForge及另外六个项目的固定版本研究](../../../research/novel-workbench-comparison-2026-10-15.md)，独立实现以正文为中心的三栏工作台。左栏切换章节目录与人物知识，中间编辑正文，右栏显示写作总管、候选和本章依据。三栏独立滚动；同一章内查看证据或保存人物资料不重建正文输入框，保留选区、正文滚动及专注显示状态。专注显示可收起两侧；字号、行距的本机偏好尚未实现。

写作总管使用固定版本 `langgraph==0.6.11` 和 `langgraph-checkpoint==3.0.1`。LangGraph负责步骤与中断，墨屿的服务端负责作品/分支隔离、来源冻结、调用限制和作者确认。任务计划、检查点和队列在同一SQLite事务中保存，提交成功后才启动后台执行，不依赖页面一直打开。

| 模式 | 自动协调与作者决定 | 单次计划上限 |
| --- | --- | --- |
| 续写 | 生成候选，作者比较采纳后自动接章后记忆与故事审稿 | 3次模型请求 |
| 整章修订 | 冻结完整原稿、版本、指纹和范围；作者采纳修订后接记忆与审稿 | 3次模型请求 |
| 章节检查 | 对当前已保存稿执行章后记忆和故事审稿 | 2次模型请求 |
| 全书规划 | 总纲、分卷、章节、场景逐阶段确认后接续；最终明确采用才更新蓝图 | 4次模型请求 |

整章修订拒绝空稿或超过12000个完整字符的稿件；材料容量不足时也先拒绝，不把正文尾段冒充整章。全书规划沿用现有规模，空蓝图默认1卷、每卷3章、每章2场景；上限3卷、每卷8章、每章4场景。章节任务检查原稿、已消费资料与模型设置；全书规划检查蓝图与模型设置，单纯修改正文不会使规划失效。

刷新和重启回读已有任务；重复确认不会重复排队。执行或费用未知时停止并保留候选，不能自动重发。取消不承诺远端停止计费。章后记忆仍逐项确认后才能成为正式事实，审稿结果仍须作者处理。完整ZIP带走总管历史；恢复副本中的旧任务只供阅读，不能重放旧检查点。

本轮还修复完稿作品仍显示新建章节入口、超容量提示的语言，以及总管操作收到数组、对象等非法类型时返回内部错误的问题。非法操作明确拒绝，48次真实HTTP请求逐次核对全库保持不变，不调用模型或启动后台任务。长篇目录切章后回到开头的问题也已修复，目录与异步规划回读保持位置并使当前章可见，正文与主页面不被滚动。

## 长篇规模与待办

300/1000章的本机合成作品已执行首开、切章、逐字输入和SQLite正文核对，数据和环境见[长篇基线](long-workbench-baseline.md)。1000章首次进入约302ms、切章中位约100ms，三轮输入处理p95为25.6–27.9ms；六轮保存逐字一致。它只衡量指定机器与合成数据的编辑表现，不能作为真实作者效率或无限规模能力的结论。目录修复后另用1000章沿六个前后跳章位置复核，当前章可见且正文一致；不以此作为速度前后对比。

当前仍整本读写作品状态，1000章时一次保存发送与返回各约5MB；即使合成量测没有丢字，也存在随规模增长的数据处理成本。跨章位置恢复、数小时连续编辑、完整双向知识链接、Obsidian双向同步、跨章自主批次和可复用写法版本库尚未完成。右栏的待处理数字仅统计运行任务或待确认记忆，不是全书待办总量。

七个上游项目本轮只做固定提交源码研究，没有运行其完整产品。墨屿工程通过只证明本次流程与数据保护，不证明模型文学质量、真实检索和审稿准确率。文学共享预算仍为56/60次预留、剩4次，未提高额度；没有完整合格的对照与盲评，不能宣称达到第一梯队。
