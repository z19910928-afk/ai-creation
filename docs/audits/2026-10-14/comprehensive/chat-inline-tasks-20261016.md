# 在聊天原卡管理写作任务

批次及完整整轮执行日期为2026-10-16，本文整理日期为2026-10-17，上海时间。范围：单人本机电脑创作，不包含手机端。

本批让多步写作建议确认后留在主页面的原聊天卡片，作者随时查看、启动和核对，不必先跳到管理页。完整整轮03、独立复核及本机两尺寸只读预览已通过；下列定向、整轮与实际预览分别记录。GitHub状态以本次最终提交对应的实际运行结果为准，本机通过不代替云端检查。

## 作者流程

1. 在右侧写作总管中讨论，点击“确认此步骤”保存需要执行的建议。
2. 原卡显示来源章、准确任务状态和“模型调用 已用 / 上限”；核实身份、来源与进度后，提供“启动本次任务”。
3. 作者启动本次任务，页面先保存正文和未保存的规划，再核实最新任务记录；保存失败不发送写作请求。
4. 原卡更新执行状态。“核对进度”只读取本次任务；需要处理候选或资料时，点击“查看本次结果”打开原章及准确任务。
5. 正文比较后由作者采纳，章后资料逐项决定；规划逐阶段确认，完整规划另行采用。

| 卡片状态 | 可用操作与边界 |
| --- | --- |
| 正在核对、状态未核实或读取失败 | 重新核对原任务，暂不提供启动入口 |
| 等待启动且身份、来源有效 | 查看来源与调用上限，启动本次任务 |
| 正在执行或已有结果 | 核对进度，按需查看本次结果 |
| 正文候选待采纳、等待章后确认或规划待确认 | 打开对应结果，由作者完成相应决定 |
| 来源变化、来源章不存在或需要处理 | 查看原因，按当前资料重新讨论，旧卡不能继续启动 |
| 历史只读、任务结果未确认或启动结果待核对 | 保留记录并读取原任务，不自动重发启动 |

“查看本次结果”使用该建议保存的准确任务编号与来源章，不取同章最新任务替代。来源章改名后更新名称，来源章消失后撤销启动资格。选区修订仍进入引用原文对应章节的候选比较，不属于上述多步计划启动。

## 授权与保存

- “确认此步骤”仅保存多步计划，“启动本次任务”才授权这次写作流程。确认计划、核对进度和查看结果不调用该写作模型；普通聊天回复另计调用。
- 续写或整章修订最多三次、章节检查最多两次、全书规划最多四次模型调用。聊天和写作共用每日额度，次数上限不是金额保证。
- 正文采纳后沿已授权流程整理章后资料；事实、回顾和交接全部保存决定后接续审稿，无需每一步再次手动启动。可以分次保存或全部不采用，空分析也需明确保存一次决定。
- 全书规划逐阶段等待作者确认，确认后接续下一阶段；四阶段完成后另行“采用完整规划”才更新蓝图。
- 启动回应丢失时只读取原任务，保留作者草稿；结果仍不确定时隐藏启动入口，不自动重发。完整备份恢复的旧任务继续只读。
- 任务与会话继续保存在本机SQLite（保存作品的数据库文件），聊天草稿按作品、分支和对话保存在当前浏览器。本批未新增接口、框架或数据库表；凭据仍仅保存在本机，不进入作品备份或仓库。

本轮同时修复查看结果时的切章保护：保存等待结束、第一次任务读取结束及后续打开任务时，重新核对点击时的章节和聊天范围。作者已切换聊天、章节、作品或分支时，迟到回应不得改变新位置或带入旧任务焦点。
