# 章后确认与总管接续

日期：2026-10-16，上海时间。范围：电脑端总管、章后资料确认、审稿接续与来源校验。

## 修复的问题

旧流程在章后提取完成后立即启动审稿。隔离服务的真实接口复现确认：作者随后正常保存章节回顾和下一章任务，会使已经完成的审稿过期；如果审稿还在生成，结果保存可能因资料变化而失败。总管仍可能显示旧的完成状态。旧报告允许作者解释后恢复归档，因此不能将此问题描述成必须再次付费审稿。

## 当前流程

正文候选由作者比较、采纳，随后总管整理章后资料。检查模式直接从章后提取开始。

1. 提取成功后，总管保存 `awaiting_memory` 等待状态，并提供“确认章后资料”。
2. 每项事实、章节回顾和下一章任务由作者决定采用或不采用。已处理内容锁定；空白的回顾或任务无需填写。
3. 可以分次保存。未处理完时保持等待，核对进度、刷新和只读读取均不新增模型调用。
4. 全部决定提交后，再使用当前已确认资料启动故事审稿。接受与拒绝均可完成确认，不强迫采用模型建议。
5. 保存后进程中断时，重启恢复原任务；重复确认、回调和进度更新不重复建立同一步骤。

全空的提取仍需要作者明确保存一次决定，再继续已授权的审稿。已确认的同来源分析可被另一条单独授权的任务复用；每条任务只建立一份后续审稿。检查最多两次模型调用，续写和整章修订最多三次，没有增加调用上限。

## 数据与确认边界

- 任务入口按该任务保存的分析编号打开结果，不会误开本章较新的另一份提取。
- 原始请求、模型返回和生成依据保持不变。新接续只接受对应分析保存的作者决定，仍核对正文版本、材料与创作约定，以及完整请求指纹。
- 作者确认自身造成的回顾、交接和正式资料更新，可以成为下一步依据。其他正文、材料、规划或模型设置变化仍会阻止继续，不能通过无条件刷新来源绕过检查。
- 确认接口先提交作者决定，再通知总管。只读接口不推进流程；停止的任务不会因后续手动确认而恢复。
- 数据继续保存于本机作品数据库。完整备份保留任务与检查点原件，恢复为只读历史，不复用原任务收费执行。
- 旧版已完成或已失败任务不自动重新审稿；作者可按当前正文建立新的检查任务。既有审稿的作者解释入口保留。
