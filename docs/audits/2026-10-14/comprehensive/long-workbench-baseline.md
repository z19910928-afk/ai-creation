# 电脑端合成长篇工作台量测

日期：2026-10-16，上海时间。范围仅为 1440 x 1000 电脑端、隔离合成作品。
本附件补充[电脑创作工作台与写作总管验收记录](writing-workbench-agent.md)。
这是编辑表现和目录可见性的证据，不代表文学质量、真实作者效率或同类产品排名。

两组基线报告中的 Python 均为 3.11.17、SQLite 均为 3.53.1，保留默认 `bigram`
搜索索引，没有通过禁用索引改善结果。基线时同机负载约为 3 至 4。

基线在上海时间 00:28:09 至 00:28:30 完成。每组使用独立临时 SQLite，
不使用真实作品。子进程环境仅保留必要白名单，模型凭据为空；服务端模型、后台
worker 和对外 HTTP 入口均设置阻断与计数；浏览器仅允许访问该组临时本机服务。

HTTP 读取包含本机实际请求、响应正文读取和 JSON 解析，不是直接读取数据库。
首次工作台包含页面导航、状态加载和进入创作工作台。切章时间包含真实点击、
当前章匹配及连续两次 `requestAnimationFrame` 后的等待，不等于纯渲染耗时。
输入通过 Chrome `Input.insertText` 每约 100 ms 提交一个中文字符；每轮完成后
等待保存稳定，再实际 HTTP 读取正文，与编辑器内容逐字核对。

横向溢出或浏览器外联；服务端模型、worker、对外 HTTP 调用计数均为 0。
1000 章三轮输入处理 p95 均高于常见的 16.7 ms 单帧预算，同时出现 7 个长任务。
本次没有丢字或保存失败，但整本缓存、比较、字数计算和整书 PUT 的成本仍随规模增长。
下一轮性能工作应减少每字整书处理和整书传输，再量测实际收益。

## 限制与来源

- 材料是重复合成文本，未覆盖真实作者的复杂知识图谱、超长标题、附件与大量历史任务。
- 未降速；数据库与系统缓存已热；其他验收可能并行，不能外推低配机器或冷启动。
- 直接提交中文字符，没有覆盖输入法候选、拼音组合、粘贴大段与数小时连续编辑。
- 只测试电脑端；未测手机端，符合本轮范围。
- 工程验收不等于文学质量、真实检索准确率或故事审稿准确率，也不能证明“第一梯队”。

两份公开 JSON 都从 `artifacts` 中已存在的脱敏归档原样复制，复制前后 SHA-256
一致，没有重写数值、移除失败样本或覆盖旧报告。随机本机端口及绝对临时目录已在
原归档中替换，公开副本不再做二次转换。
