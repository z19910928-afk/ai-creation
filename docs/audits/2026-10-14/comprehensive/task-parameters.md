# 分用途模型参数

上海2026-10-15的B1实现与验证。续写、润色、大纲、场景、总结、检查、灵感、章节分析和语义审稿可以各自保存模型参数与输出上限。12方法HTTP专项、20场电脑浏览器定向检查及 `task-parameters-release-20261015` 新完整整轮均通过，整轮公开证据经独立只读复核。此记录本身不证明真实模型文学效果、生产更新、GitHub检查或第一梯队验收。

## 已实现规则

公开设置字段 `task_parameters` 保存作者填写的用途对象，支持9种用途。每个用途允许温度、输出上限、采样范围、重复惩罚、随机种子、停止词、思考强度和思考开关，校验沿用原模型请求规则。未知用途、未知参数、非法数值和互相冲突的思考设置拒绝保存，整次请求回滚，不能顺带替换密钥。

| 行为 | 已实现合同 |
| --- | --- |
| 省略 `task_parameters` | 保留已有用途对象 |
| 传整个 `{}` | 清除全部用途覆盖 |
| 单个用途为 `{}` | 移除该用途覆盖；其余传入用途保留 |
| `temperature:0`、`top_p:0`、`seed:0` | 保存原零值，不当成空值 |
| 用途输出上限 | 显式请求上限优先，其次用途上限，最后全局上限；合法范围1至128000整数 |
| 其他用途参数 | 覆盖全局同名参数；缺失字段回到全局 |
| 总结/检查兼容名称 | 未显式覆盖时，`summary` 整个对象用于 `chapter_analysis`，`check` 整个对象用于 `semantic_review` |
| 显式分析/审稿覆盖 | 使用显式完整对象，缺失字段回全局，不从总结/检查对象补字段；清除后恢复兼容名称规则 |
| 思考字段 | 更具体的思考开关或强度替换继承层的另一种表示，不因继承出现假冲突 |
| 电脑用途表单 | 直接读写原始用途对象；清除按钮移除整个用途参数对象，保留模型名称与其他用途；普通编辑保留未显示的合法参数 |
| 空值提示 | 无显式分析/审稿对象时，显示沿用回顾/检查；有显式对象时，空项显示沿用全局，源用途尚未保存的编辑也会立即更新提示 |
| 全局温度空白 | 保持缺失语义，重开/刷新显示空白及“按用途默认”，不把缺失值显示或重新写成统一0.65；零值仍保存0 |
| 已建队列和原请求重试 | 冻结原模型、参数、输出上限和请求内容；后来改设置不改变旧任务 |
| 未知是否完成/计费 | 两个重试入口继续拒绝，不能借新参数重复发送 |
| 完整ZIP | 保留合法公开用途偏好，清除凭据及未知字段；恢复作品使用独立凭据 |

内部发送设置把用途采样参数与输出上限分开，避免把 `max_tokens` 当作普通采样字段提交。创建规划任务使用同一任务创建入口。实现范围是 [设置保存](../../../../moyu_settings.py)、[预览与任务创建](../../../../server.py)、[完整备份](../../../../moyu_backups.py)。
