## 模型调用证据

`moyu_provider.py` 负责一次模型请求，`moyu_settings.py` 负责作品设置和本机私密凭据。请求地址、模型、消息、参数、输出预算、请求指纹、返回模型、结束原因与用量都可追查。密钥不进入数据库、作品备份、任务公开回读或评测文件。

凭据单独保存到 `~/.moyu/credentials/`，目录权限为 `0700`，文件权限为 `0600`。`MOYU_CREDENTIALS_DIR` 可以指定受控目录。变更密钥产生新引用，因此撤销设置事务不会损坏已排队任务。恢复到其他设备或独立作品后需重新配置密钥。

请求先原子预留作品每日额度，再释放数据库写锁并调用模型。最多两个模型任务同时执行。每个正文分片立即落库，正文保存和其他操作可继续进行。分片序号必须连续，累计指纹覆盖此前正文，完成时重复保存同一分片不会重复文字。

结束原因有明确区分：

- `stop`、回复正文有效且任务输出要求通过：候选可以进入作者比较。协议结束本身不等于内容、字数或事实合格。
- `length`：输出截断，保留供查看，禁止直接采纳。
- `content_filter`、拒绝或工具调用：不作为完整正文。
- 缺少结束原因、流未正常结束或断线：状态未知，不当作成功。
- 取消：关闭本机连接，保留已到达正文；无法保证远端立即停止或取消收费。

连接与等待 HTTP 头、非流式模型思考采用总等待上限。流式回复开始后另设分片空闲上限。总上限始终有效；不会因长思考把尚未到达的 HTTP 头当成分片超时，也不会无限等待。

不自动跟随重定向或重试可能已收费的请求。重启时外部运行中任务变成未知，需要核实提供方用量；不会自动重发。连接测试消耗同一每日额度，失败仍保留账本，设置期间变更时旧测试不会标记新配置健康。请求名称和返回名称分别记录，名称相同也不能证明底层模型身份。

返回和失败结果都保留有界的协议字段形状：字段名、类型、长度、结束原值及事件序号，不保存思考内容。最多保留开头 112 条和最后 16 条，因此流末尾的未知结束原因仍可核查。未知原因不会当成 `stop`，只有思考而没有正文的回复不能当作候选成功。

原始用量字段保留不改，另由 `usage_accounting` 记录证据状态：

- `reported`：可信的总数，或同时具有完整输入和输出计数、可推导出总数；来源分别为提供方总数和分量推导。
- `partial`：仅有一项分量，或流式观察只支持部分计数；只保留已知用量下界。
- `inconsistent`：总数与分量矛盾、流式累计计数倒退，或原始字段与保存的观察不一致；保留已经观察到的较高下界，不能当成完整用量。
- `unknown`：没有可信计数；下界为零表示尚无证据，不表示请求免费。

`total_tokens` 仅在完整可信时有值，`reported_tokens_lower_bound` 单独记录下界。历史 `billing_state=usage_reported` 不能替代原始字段与观察的重新核对；缺失、部分或矛盾用量仍按缺少可信完整用量处理。已知完整 tokens 也不等于已核实实际金额。

普通创作任务另以 `moyu_output.py` 检查字数、明显思考标签、伪结构和审稿任务所需的原句证据。未通过的返回仍保留候选与原因，不能直接采纳，不自动截短、补写或再次收费。真实模型返回 `stop` 但违背600至850字等要求时，页面和后端都应明确阻断；输出检查不是文学质量评分。

分阶段规划使用同一持久化模型队列，固定原蓝图版本、内容指纹与实际请求，按总纲、卷、章、场景四步生成并由作者逐阶段确认。明确失败时只手动重做当前阶段；执行未知的请求保留原任务，禁止重发。完整确认后的采用只更新蓝图，不写正文；同一状态和错误的重复轮询不追加事件。完整备份恢复保留候选、冻结指纹、已采用历史、源/结果版本和身份映射，历史规划只读，排队或运行中的请求保留为未知，不继续确认候选或再次外发；副本要调用模型需重新创建规划。

## 默认试评方案

`scripts/literary_evaluation.py plan` 先生成方案。默认六个原创故事题目，覆盖悬疑、科幻、现实情感、武侠以及续写、润色、审稿、总结。每题含完整当前正文、上一章、已知事实、作者要求和生成前固定的事实规则。

默认两种方法：通用固定材料基线、墨屿实际提示。两者共享素材、写作模型、参数、输出预算及流式设置。首次生成前保存全部实际请求的原始字节和指纹。续跑使用原请求，不重新套用修改后的提示；源码指纹用于审计。已预留的请求禁止自动重复。

首次冻结还会在 `run.json` 保存独立的 `run_id`。候选生成和评审的对外请求编号都包含这轮身份；同一目录续跑保持身份，新目录重新冻结产生新身份，因此相同题目不会与旧轮次复用对外编号。复制已经冻结的目录仍属于同一轮，不能用它开始新评测。旧版本缺少这项身份的记录继续可供匿名展示和报告读取；生成和评审会在发送前停止，不改写旧运行或账本，需另建目录冻结新轮次。

协议完整与候选输出合格分别记录。`sample_validation` 要求完整正文、正常结束原因和有效文本；续写的600至850字、润色的原文80%至130%等明确要求单独检查。字数按非空白字符计算，包括标点；新方案把上下限冻结在每题的 `output_contract`，旧方案仅从明确的字数指令读取。不改写、截短或删除原候选；不合格文本保留用于诊断，匿名对照时排除。明显的“我们需要回答”“创作思路”或思考标签也会标记并排除。标记检查只能发现部分污染，通过不证明没有污染或文学质量合格。

试评默认需要十二次候选生成。两个不同评审模型分别以 A/B 和 B/A 顺序比较六对匿名候选，共二十四次评审。评审不能使用本次写作模型，只看相同素材、规则与候选，不获知方法名称。规则违规必须逐字引用候选中的实际原句，虚构引用判无效。双顺序偏好发生改变时保守记平，并报告变化次数。

方案必须要求至少两种不同评审模型，不能把最低门槛改为一种。报告的最低有效评审数量由计划候选对数、最低评审模型数和双顺序共同计算，默认始终为二十四次；实际一条评审都没有时也显示 `0/24`，不会用已收到的模型数把分母降为零。

发送评审前会核对匿名文本、固定素材、规则和原始候选，评审记录保存 `pair_sha256`。报告重新检查候选及对应快照，不信任已保存的检查结论；旧评审缺少快照指纹不能作为有效证据，也不会自动重发。不同评审名称返回同一实际模型时不算两种独立评审；返回写作模型的别名自评判无效。

当前报告分别列出 `planned_genres`、`observed_genres`、`eligible_genres` 和 `reviewed_genres`：计划题材、已有返回记录的题材、至少一份候选输出合格的题材，以及双方候选合格并完成至少两种不同实际返回模型双顺序有效评审的题材。失败候选也保留实际请求与返回模型身份，因此“已有返回”不表示成功生成。最低题材覆盖门槛只使用完成评审的题材；任务或题材与冻结方案不符的候选不能计入。第三至第十一轮原始报告保留原字节，不用当前统计规则回写历史结果。

独立故事同时报告计划、实际返回、至少一份候选输出合格和每个对照的完整评审数量。每个对照只计入双方候选合格、两个不同实际返回评审模型均完成双顺序的故事，第一梯队故事数量门槛固定为各30个。计划30个、生成30个、单模型评审、缺一个顺序或返回同一实际评审模型都不能通过。多对照中某一对照达30个也不能替其他对照达标；任务或题材被篡改的记录拒绝计入。

置信区间以独立故事为单位。故事按冻结方案的 `story_id` 合并，未指定时使用题目编号；身份标签本身不能证明故事内容独立。同一故事的重复生成、两个评审模型和双顺序不能扩大独立样本数量。模型评审仍可能误判，需要人工复核；不同模型名称不证明训练来源或观点完全独立。

任何单次有效评审指出的事实违规都会立即保留，不能因另一顺序未完成而忽略。`pilot_evidence_complete` 仅表示输出检查合格、题材覆盖和评审证据齐全；`pilot_quality_passed` 还需要硬事实违规率不超过冻结上限、独立故事偏好的置信下界达到阈值。违规率必须覆盖全部待评候选，零条标记不等于已证实无违规。两项都不证明第一梯队。

六题试评不能证明第一梯队。工具明确输出 `first_tier_proven: false`。至少三种已完整评审题材、每个对照三十个完整评审的独立故事只是必要证据之一，还需七竞品实际对照、完整作品检索、数据恢复、真实作者采纳率和修改时间。

## 费用和停止条件

默认总请求上限为六十次，已知用量下界的停止阈值为十八万 tokens。请求上限是硬闸；发送前把每次请求的已知下界相加，完整、部分和矛盾计数的已知部分都会计入停止判断。当前请求可能超出阈值，未知部分仍不在这个合计中。未知用量、取消收费和未知价格都不能当作零。

报告的 `reported_tokens` 只合计可信完整总数，`reported_tokens_lower_bound` 另列全部已知下界。`requests_without_usage` 包含无用量、部分用量和矛盾用量，另列后两项数量；这些请求都缺少可信完整用量。连续失败停止规则也重新核对原始计数，不允许历史费用状态把未知改成已知。

连续两次失败且费用未知时自动停止，保留账本，不重试。发送前同步保存账本和候选的发送意图；任一保存失败都会停止本次发送。发送意图表示随后可能已发送，不能单凭它断言提供方收到或收费。已确认发送前取消的终态保留意图历史，并标记没有发送。

人工中断且尚未收到完整结果时记录为未知，保留已经到达的正文、用量和协议证据；只有用量事件已到而结束标记未到时，也不能丢弃已知用量。已收到完整结果后中断则保留完整结果。带发送标记的 `reserved` 记录在续跑时转为未知并保存原始检查点，不会重发。如果候选和账本只有一边保存最终结果，先核对请求身份、指纹、地址和模型后再恢复；不一致时保留原始证据并停止。旧版本没有发送标记的 `reserved` 记录保持原样，先核实外部执行，不能删除记录来触发再次执行。

`--max-new-requests 2` 可把本次执行限制为最多两个新增请求，再次执行只发送新身份的请求。每个目录独立计次；换目录做诊断时仍须合计旧目录和诊断已经发生或费用未知的请求，不能把新目录当作费用归零。

默认只比较固定材料下的两套实际提示，不冒充运行七个应用的完整创作流程。新增对照可用 `frozen-requests` 方法，必须导入其实际请求、对应任务及素材指纹；不能只换一个系统提示就写成竞品实测。

## 执行方式

运行环境提供 `MOYU_AI_BASE_URL`、`MOYU_AI_MODEL` 和 `MOYU_AI_API_KEY`。不要把真实密钥写到脚本、命令文本、日志或报告。真实调用由已获授权的执行者运行 `--execute-paid`；普通命令不会发送收费请求。

```sh
python3 scripts/literary_evaluation.py plan --output-dir /absolute/path/to/new-run
python3 scripts/literary_evaluation.py generate --output-dir /absolute/path/to/new-run --max-new-requests 2 --execute-paid
python3 scripts/literary_evaluation.py blind --output-dir /absolute/path/to/new-run
python3 scripts/literary_evaluation.py judge --output-dir /absolute/path/to/new-run --judge-model JUDGE_ONE --judge-model JUDGE_TWO --execute-paid
python3 scripts/literary_evaluation.py report --output-dir /absolute/path/to/new-run
```

更改题目、模型、参数或流式设置时，在首次调用前修订方案并使用新目录。为所有方法统一设置 `"writer_stream": true` 可启用分段回复；不能把改变后的请求混到原运行中。

目录包含：

- `plan.json`、`frozen-plan.json`：预先方案和素材。
- `run.json`、`frozen-writer-requests.json`：独立运行身份、源码、方案与实际请求快照。
- `request-ledger.json`：每次预留、状态、实际用量与费用未知情况。
- `samples/`：完整或失败候选，及实际发送请求审计。
- `blind-review.md`、`blind-pairs.json`：匿名对照。
- `blind-key-private.json`：单独的方法映射，不交给评审，Git 已忽略，不提交到公开仓库。
- `human-ratings-template.json`：作者采纳和修改时间记录模板。
- `grades/`、`report.json`、`report.md`：评判、证据闸和统计范围。
- `reconciliations/`：异常中断恢复前的原始账本和候选检查点，保留恢复原因和禁止重试记录。
