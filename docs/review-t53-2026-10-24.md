## 五、findings

### F1（medium）引文闸门不覆盖断言语义，`subject`/`value`/`attribute` 可与引文无关

- **现象**：`backend/moyu_extract.py:223` 的 `verify_evidence()`（:223-232）只比较
  `text[char_start:char_end] == evidence_quote`；`validate_assertion()`（:156-220）只做 schema
  与区间形状。两者都不检查主语、取值、槽位是否由引文支持。
- **实测**：引文 `年方十六`（区间真实）搭配 `subject=林黛玉 / value=99`（F1e）或
  `attribute=height / value=1.2`（F1f）均通过；注入 provider 后 `extract_chapter` 原样返回
  （G6a）。即：**伪造引文不可能，伪造断言可以**。
- **承诺边界**：模块 docstring 第 8 行写「这里只保证『抽得出来、幻觉进不去』」，
  `docs/real-corpus-extract-2026-10-24.md` §3 标题为「防幻觉：三道闸门」，但三道闸门全部
  只作用于引文与区间；§8 七条已知局限里没有这一条。
- **影响**：LLM 模式下模型可引用一句真实原文、却给出错误主语或数值；该断言进入
  `assertion` 表后会参与一致性检查，制造真实数据里不存在的「冲突/漂移」。规则模式因为
  取值直接从原文切出，不受影响；**受影响的是尚未跑过真模型的 LLM 分支**（§8.1 已承认无真产出）。
- **requiredFix**：二选一或并用——
  1. 收敛口径：把 docstring 第 8 行改为「引文与区间不可伪造」，§3 标题改「引文闸门」，
     并在 §8 增加第 8 条局限：「不校验 subject/value/attribute 与引文的语义一致」；
  2. 低成本加固：`has_attribute` 时要求 `str(value)`（或其中文数字形态）出现在 `evidence_quote` 内，
     且 `subject` 出现在引文或 `_nearest_subject` 的 30 字窗口内；不满足记 `quote_mismatch` 或新增
     `unsupported_claim` 原因码。
- **不升 high 的理由**：t53 的代码级承诺（docstring 第 12-14 行、docs §3 表格）明确只针对引文
  切分；引文本身确实不可伪造，且规则模式（当前唯一实际产出路径）取值来自原文。风险集中在
  未启用的 LLM 分支 + 文档措辞。

### F2（low）`NaN`/`Infinity` 通过 `value` 类型检查，序列化出非法 JSON

- **现象**：`backend/moyu_extract.py:189-190` 用 `isinstance(value, (str, int, float, bool))`
  判 `value`；`float('nan')` 通过，`json.dumps` 输出 `{"value": NaN}`——RFC 8259 不允许的字面量。
- **实测**：S3s，`json.dumps(validated)` 含 `NaN`；`digest()` 也会把 `NaN` 写进被哈希的 JSON。
- **影响**：Python 侧自洽（两次哈希相同，D4a/D4b 不受影响），但严格 JSON 消费方
  （其它语言、`json.loads` 之外的工具）解析失败；属边界输入漏洞。
- **requiredFix**：`validate_assertion` 对 `float` 增加 `math.isfinite(...)` 检查，不满足记
  `bad_range`；或在 `digest()` / 基准输出用 `allow_nan=False` 并转成 rejected。
- **不升 medium 的理由**：正常 JSON 输入的 provider 不会产生 NaN（`json.loads` 默认不接受
  `NaN`）；只有 Python 侧直接构造 dict 才会触发。

## 六、残余风险（未验证，明示）

1. **LLM 分支没有真模型产出**（与 t53 §8.1 一致）：本机无 `MOYU_EXTRACT_*` 凭据，复审只覆盖
   协议构造、解析、降级、确定性；真实召回率与幻觉率仍未知。F1 的风险量级也因此无法实测。
2. **召回率**：规则模式在「贾宝玉年方十六」这类无「姓X名Y」开场的句子上不产出（实测 0 条），
   与文档「宁缺勿错」一致，不视为缺陷。
3. **性能**：本机 20 章 2.218 ms、360 章耗时可复现；未做并发/大文件压力测试。
