## 五、新问题

### F1（low）自定义 provider 的异常原文未经脱敏就进 `rejected`（非 t69 引入）

`backend/moyu_extract.py:889-894`：

```python
    try:
        raw = callable_provider(text, chapter_id)
    except ExtractProviderError as error:
        _reject(error.reason, error.detail)          # provider 层已脱敏
        raw = []
    except Exception as error:  # noqa: BLE001 - 自定义 provider 崩了也不许拖垮整章
        _reject("provider_error", f"{type(error).__name__}: {error}")   # ← 原文
        raw = []
```

`OpenAIProvider` 会把所有传输层异常包装成已脱敏的 `ExtractProviderError`（`:522-529`，
我的探针 F 验证过），所以默认路径安全。但 `extract_chapter_report(provider=<自定义可调用>)`
时，第三方 provider 抛出的任意异常消息会被**原样**写进 `rejected[].detail`，再随报告 JSON 落盘：

```
provider = lambda text, chapter_id: (_ for _ in ()).throw(
    RuntimeError("upstream 500, authorization header carried <synthetic-secret>"))
→ rejected[0] = {"reason": "provider_error",
                 "detail": "RuntimeError: upstream 500, authorization header carried <synthetic-secret>"}
```

> 说明：上面的示例为说明旧实现会原样落盘 header 内容，使用占位符而非真实凭据；原始探针使用的是合成 key，不是用户凭据。

可达性：需要调用方自备 provider 且其异常消息里带凭据（benchmark 默认走 `OpenAIProvider`/`dry_run`，
不触发）。危害：报告与基准产物会持久化凭据。属既有行为，t69 未触碰该行。

**requiredFix**（任一即可）：
1. 该分支只保留 `type(error).__name__` 与固定文案（如「provider 抛出未预期异常」），不带 `{error}`；
2. 或给 `extract_chapter_report` 增加可选 `redact` 回调，由调用方注入凭据脱敏；
并补一条 fixture：自定义 provider 抛含 key 的异常 → 断言 `rejected[0].detail` 不含 key。
