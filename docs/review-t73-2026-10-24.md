## 五、findings

### F1（medium）全角标点后紧跟凭据键时，下一个值会裸奔（并吞掉中文诊断）

- 位置：`backend/moyu_extract.py:580-582`
  ```python
  _AUTHORIZATION_RE = re.compile(
      r"(?i)\b(authorization\b\s*[:=]\s*)(?:[a-z]{3,12}\s+)?[A-Za-z0-9._~+/=\-][^\s,;]*"
  )
  ```
  值的终止字符只有 ASCII 空白、`,`、`;`。`；，、：` 不在其中，于是 `[^\s,;]*` 会跨过全角标点继续吃，把紧随其后的 `x-api-key:` 这类**键名**一起吃掉；键名消失后，`_CREDENTIAL_PAIR_RE` 再也匹配不到那一对，该键的**值**就留在 detail 里。
- 复现（单位级，`_mask_credentials` 直调）：
  ```
  输入: HTTP 502：Authorization: Bearer Zx9Qw8Er7Ty6；x-api-key: xapi-9f8e7d6c5b4a3210
  输出: HTTP 502：Authorization: *** xapi-9f8e7d6c5b4a3210      ← 值裸奔
  ```
  端到端（`/tmp/probe_t74.py` H/X 组同源脚本）：`extract_chapter_report` 的 `rejected[0].detail` 持久化了 `xapi-9f8e7d6c5b4a3210`；同一输入把分隔符换成 ASCII `;` 后为 `Authorization: ***; x-api-key: ***`（正确）。
- 分隔符矩阵（Authorization 值 + `x-api-key:`）：`;` / 换行 / 半角空格 → 全部抹净；`；` `，` `、` `：` → 4/4 裸奔。
- 顺带的数据丢失：`Authorization: Bearer <tok>；上游拒绝` → `HTTP 502：Authorization: ***`，`上游拒绝` 被吞；`；error code 1010` → 只剩 `code 1010`（`error` 被吞）。也就是说同一根因同时造成**脱敏不足**与**诊断丢失**。
- 为何是 medium 不是 high：触发需要「`Authorization` 值后紧跟全角标点 + 紧邻另一个带键名的凭据，且中间无空格」。中文错误文案里 `；` 很常见，`Authorization` 与第二个凭据同时出现则较少；一旦命中，泄漏的是被持久化的报告字段。
- 建议修复：把值终止符扩到全角（`[^\s,;，；、：]*`），或干脆只抹「scheme + 一个 token」两段，不要用开区间字符类。并补一条 `；` 分隔的 fixture（现有 `auth_plus_api_key` 用的是 ASCII 空格/逗号，覆盖不到这个分支）。
- 用例缺口证据：`tests/extract_fixtures.py` 的掩码用例里没有任何全角标点组合。

### F2（low）`_SCHEME_TOKEN_RE` 注释声称覆盖 Basic，正则里没有 basic

- 位置：`backend/moyu_extract.py:587-590`。注释写「（Bearer/Basic/Token/Digest）」，正则实为 `(bearer|token|digest)`。
- 实测：`Authorization: Basic dXNlcjpwYXNz` → `Authorization: ***`（走的是 580 行的 header 分支，正确）；但裸写法 `upstream said: Basic dXNlcjpwYXNz` → **原样保留**。`Bearer abcdE`（5 字符）同样保留（长度下限 6，属设计取舍，不计问题）。
- 影响：只影响「header 名已被上游剥掉、只剩裸 scheme」的文本；同理维护者读注释会以为 Basic 已覆盖。
- 建议修复：要么在正则里加 `basic` 并靠「≥6 字符 + 非中文」抑制 `basic plan` 误伤，要么把注释改成「Basic 仅在有 `Authorization:` 头名时覆盖」。
