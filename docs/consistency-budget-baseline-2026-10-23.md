## 2. 一次通过的定义

一个场景记为「一次通过」，当且仅当同时满足：

1. `stop_reason == "target_reached"`；
2. `within_tolerance` 为真，即累计字数落在 `[ceil(0.9×目标), floor(1.1×目标)]` 内。

引擎在累计字数达到下限（0.9 倍目标）时立即停止，因此**单轮产出过大、越过 1.1 倍上限时 `within_tolerance` 为假，本基准判为失败**，不放宽成只看 `target_reached`。这一条决定了 `volatile` 档的判定结果。

## 3. 方法

### 3.1 被测引擎

- 模块：`backend/moyu_continuation.py`，sha256 `00f6cc1419abb06f…`
- 入口：`run_budgeted_continuation(generate, *, target_characters, max_rounds, min_round_gain, budget_check, should_cancel, context_builder)`
- 字数口径：`non_whitespace_characters_including_punctuation`（非空白 Unicode 字符，标点计入、空白不计）
- 容差：±10%，下限向上取整、上限向下取整

### 3.2 fake provider 模型

基准不调用任何真实模型。每个场景注入一个内存 fake provider，它按「剩余额度 × 档位比例」决定本轮产出长度，比例带固定区间的均匀抖动，随机流由 `seed` 派生，因此完全可复现。产出的正文取自内置中文语料，长度精确、不含空白字符，保证 `count_characters` 与产出长度一致。

| 档位 | 标识 | 单轮产出模型 | 预期行为 |
| --- | --- | --- | --- |
| 一次到位 | calibrated | 单轮产出 ≈ 剩余额度的 100%±5% | 首轮即达标 |
| 渐进收敛 | steady | 单轮产出 ≈ 剩余额度的 50%±8% | 3–5 轮收敛 |
| 保守欠量 | cautious | 单轮产出 ≈ 剩余额度的 38%±4% | 5–6 轮勉强收敛，贴近 max_rounds 上限 |
| 无视预算 | volatile | 单轮产出 ≈ 剩余额度的 75%±50%（可超过 100%） | 常首轮超冲，越过 +10% 上限 |
| 产出不足 | underpowered | 单轮产出 ≈ 剩余额度的 18%±3% | 6 轮仍达不到下限 |
| 停滞 | stalling | 单轮固定 12–30 字，低于 min_round_gain=50 | 首轮即判 NO_PROGRESS |
| 预算受限 | budget_limited | 产出同 steady，但预算在第 3 轮开始前耗尽 | BUDGET_EXHAUSTED |
| 作者取消 | canceled | 产出同 steady，但第 2 轮开始前作者取消 | CANCELED |

### 3.4 配比假设（重要）

20 个场景的档位配比是**假设**，不是从任何真实模型测出来的分布。它模拟一条已接入生产、但生成质量参差的链路：生成侧合格档 13 个（65%），生成侧劣质档 5 个（25%），外部中断档 2 个（10%）。因此**总体一次通过率是配比的函数**，换一套配比就会得到另一个数字。为避免单点数字误导，§5.2 给出每个档位的收敛包络，§6 给出断点条件，读者可以按自己的质量分布重新加权。

### 3.5 确定性口径

确定性核心 = `seed` + `config` + `scenarios` + `summary`，不含任何墙钟时间。同一命令重复 2 次，核心逐字节一致，digest 为 `sha256:f3afbcf9955600e08222d2b3a9e33214c96cad1f587af2fc5fb9417b1949ca8d`。墙钟耗时属于观测值，只写入 `results/budgeted-timing.json`，**不进入 JSON / Markdown / 本文档 / stdout**，因此同一 seed 的两次运行会产出逐字节相同的全部确定性产物。

### 3.6 正文不变性口径

每个场景在运行前把一段既有正文写入独立文件，记录 sha256；运行结束后重新读取并比对。引擎的返回值只有 `candidate_only = true` 的候选文本，任何对正文的写入都会让哈希变化并被本基准捕获。

## 6. 结论：Q1 目标在什么条件下成立

1. **引擎在生成侧合格时 100% 一次通过。** calibrated / steady / cautious 三档合计 13 个场景，一次通过 13/13（100.0%），其中保守档平均 5.33 轮，说明默认 `max_rounds=6` 足以覆盖单轮产出率低至约 38% 的模型。
2. **缺口全部来自生成侧与外部中断。** 劣质档 5 个场景通过 1 个（20.0%），外部中断档 2 个场景通过 0 个（0.0%）。在本基准给定的输入模型下，每个未通过场景都能归因到产出不足、超冲、停滞、预算或取消，没有出现引擎判定与输入事实不符的情况。
3. **断点条件。** 若合格档通过率 100.0%、劣质+中断档通过率 14.3%，则劣质+中断场景占比不超过 23.3% 时，总体一次通过率仍可保持在 80.0% 以上；本次配比的实际占比为 35.0%。
4. **Q1 口径判定：未达成。** 3000 字子集 6/9（66.7%）。该子集同样包含劣质与中断场景，因此它衡量的是「引擎 + 生成质量」的系统表现，而不是引擎单独的收敛能力；引擎单独的收敛能力见第 1 条。
5. **可交付结论。** 把 Q1 的 ≥80% 写成验收指标时，必须同时写明生成侧质量前提（例如「单轮产出率不低于剩余额度的 38%、无停滞与超冲」），否则该指标不可判定——它随生成质量分布漂移，而不是随引擎版本漂移。

## 7. 已知局限

1. **这是仿真基准，不是真实模型测量。** 全部产出由内存 fake provider 生成，没有任何真实 LLM 调用；数字反映的是引擎在给定产出模型下的行为，不能当作「某模型 3000 字章一次通过率」对外引用。
2. **总体通过率是配比的函数。** 20 个场景的档位配比是人为假设（见 §3.4），换一套配比就会得到另一个总体数字。分层包络（§5.2）比总体数字更可信。
3. **fake provider 过于规整。** 真实模型的单轮产出长度有长尾、会截断、会跑题、会重复；本基准只用「剩余额度 × 比例 + 均匀抖动」建模，低估了真实分布的方差。
4. **没有建模语义质量。** 基准只测字数收敛，不判断内容是否连贯、是否重复、是否偏离大纲；一个字数达标但内容崩坏的结果在这里仍算通过。
5. **耗时不含模型延迟。** 引擎净开销是微秒级纯 Python 开销，与生产端到端延迟无关，不能用于容量规划。
6. **未覆盖 context_builder 的上下文增长成本。** 基准使用默认上下文构造器，真实接线若把全文累积进 prompt，token 成本会随轮数增长，本基准不测量该成本。
7. **max_rounds 固定为 6。** 没有扫描 1–12 的轮数上限；若生产环境放宽上限，cautious 档会更早通过，underpowered 档仍然失败。
8. **未覆盖取消/预算的时序组合。** 预算与取消各自只有一个固定触发点（第 3 轮前 / 第 2 轮前），没有测试二者同时发生或发生在其他轮次的情况。
9. **单机单次测量。** 耗时来自一次运行内的 20 个场景，没有跨机器、跨负载的重复测量，不具备统计显著性。

## 8. 复现

```bash
.venv/bin/python benchmarks/budgeted/run.py --seed 20261023
```

命令会重新生成 JSON / Markdown / 本文件，并在 stdout 打印每个场景的判定与确定性摘要 `sha256:f3afbcf9955600e08222d2b3a9e33214c96cad1f587af2fc5fb9417b1949ca8d`。退出码 0 表示**基准完整性验收**通过（20 个场景全部执行、重复运行一致、正文未被改写、5 类停止原因全部出现、报告数字自洽），**不表示一次通过率达标**；指标是否达标见 §1 与 §6。
