## 本轮清洁室实现

在不导入上游代码的前提下，墨屿增加了以下可独立验证的能力：

- **章节任务卡**：每章保存目标、视角、场景计划、伏笔动作、回顾、下一章简报和 hook；计划与正文分离，方便作者先定任务再生成候选。
- **有界上下文包**：服务端按词项命中和新近度挑选章节片段，返回章节 ID、来源范围和预算统计。上下文预览会显示估算 token、检索条目和来源 ID；系统不宣称把整本书伪装成“百万 token”窗口。
- **可追溯记忆**：记忆候选可带来源章节、原文引句、代码点/UTF-8 范围和哈希；作者确认后才创建正典 assertion，模型猜测不会直接成为正典事实。
- **章节质量门**：完成章节可执行确定性审查，检查任务卡缺失、实体引用、待确认记忆、重复段落和正文长度；结果保存为 review JSON，阻塞项在归档前要求作者处理或明确继续。
- **AI 运行记录**：每次服务端 AI 请求保存模型、提示/上下文哈希、估算 token、延迟、作者决定状态，密钥仍只从进程环境读取。
- **作者确认优先**：生成结果留在候选区；采纳、记忆确认、章节完成和全书完稿均由作者触发，并可导出 Markdown/JSON。

这些能力是产品契约的最小闭环，不能等同于完整向量 RAG、真实百万上下文或自动事实核查。

## 独立审查结论

审查重点是“设计是否已经接到运行路径”，而不是只检查文档是否写得完整。此前数据库层已有 source span、assertion、AI run 等表，但前端和服务端没有全部使用；本轮把来源、候选→正典、审查和上下文预览接入 API，并保留旧数据兼容迁移。审查仍以测试证据为准，不能因为表存在就宣布能力完成。

### 已处理的高风险遗漏

- 生成文本不再隐式写入正文或正典记忆，候选必须经过作者采纳/确认。
- 上下文接口返回来源 ID、范围和预算，避免把“取最近几章”误称为百万上下文。
- 章节完成前有可重复的质量检查，并在终稿检查中显示未通过章节。
- AI 运行记录包含提示和上下文哈希，便于回放、成本统计和发现不一致输入。
- 记忆来源 span 与章节 revision 绑定；章节正文变化后旧 span 会标记为 stale，而不是静默继续当作新证据。

### 尚未关闭的 P2/P3 项

1. **检索质量**：当前是有界词项/新近度检索；没有 embedding、中文 FTS 基准、RRF/重排、MMR 或索引新鲜度 SLA。
2. **长任务控制**：没有流式取消、持久化队列、断点续跑、并发租约或按任务的费用/配额上限。
3. **事实与冲突界面**：已有 candidate/assertion 数据，但尚未提供完整的 assertion 列表、矛盾合并、人物知识范围和时间线冲突修复 UI。
4. **导入导出**：当前重点是 JSON/Markdown；DOCX、EPUB、PDF 的安全解析、格式往返和损失清单仍待实现。
5. **部署边界**：服务面向单用户本机；没有公网认证、多人权限、加密存储、供应商留存删除证明或云端 BYOK 策略。
6. **效果评测**：fixture 可以验证协议和拒绝路径，不能证明真实模型的长篇连贯性、风格或百万上下文效果；需要中文长篇 gold set、人工 pairwise 和成本/延迟样本。

### 安全审查余项

本轮安全复核已确认上下文存在 24,000 token 硬上限、来源 span 会随 revision 失效，且外部正文按不可信故事数据处理。仍需在部署说明中明确以下边界：

- **单用户服务**：启用 `MOYU_HOST=0.0.0.0` 后，局域网可访问读写 API；服务没有账户认证和多用户授权，只适合受控本机/内网环境。
- **配置型 SSRF**：`MOYU_AI_BASE_URL` 是管理员配置项；若被不可信操作者修改，服务端可能向其指定地址发起模型请求。生产部署应固定允许的 scheme/host、使用出口代理白名单并隔离服务网络。
- **状态接口信息**：`/api/ai/status` 会返回 provider 的 base URL 等配置状态；在共享网络上应将该接口置于受保护的管理面，或只返回是否已配置。
- **资源与完整作品暴露**：`/api/state` 会返回完整本地作品，`/api/events` 允许单次受限但可重复写入事件；公网或局域网部署仍需认证、配额、速率限制和审计留存策略。

这些是部署前需要明确的剩余风险，不代表上下文预算或 source span 已失效。

## AI 写小说的已知失效模式

以下风险属于模型能力和产品交互的共同问题，不能只靠扩大上下文窗口解决：

- **事实漂移**：模型会把候选、推断和正典事实混在一起；必须显示来源并要求作者确认。
- **时间线和人物状态冲突**：完整上下文仍可能重复死亡人物、改变年龄或越过未发生事件；需要章节任务、时间线和状态检查。
- **伏笔提前揭示/遗忘**：检索相似文本可能暴露秘密或漏掉长期伏笔；伏笔应有状态、允许的揭示范围和作者控制。
- **指令注入**：正文、导入文件和记忆可能包含“忽略系统指令”等文本；它们必须作为不可信故事数据，不能取得系统指令地位。
- **风格坍缩和重复**：续写容易套模板、复用段落、过度解释；需要重复检测、候选比较和人工编辑，而不是自动覆盖。
- **上下文稀释**：把一百万 token 全塞给模型会增加成本和噪声，不能保证记住关键事实；应先压缩、检索、分层并报告实际预算。
- **代理越权**：自动工具若能直接写文件、改正典或发布，单个错误就会扩大；所有高影响操作应产生候选 patch、审查记录和可撤销事件。
