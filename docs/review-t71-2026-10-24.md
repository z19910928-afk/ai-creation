## 二、t70 F1 的根因是否真的关闭

t70 F1 的根因是结构性的：**通用异常分支把 `f"{type(error).__name__}: {error}"` 写进 detail**。
t71 的做法不是「给这句话加掩码」，而是**整段原文不再落盘**（`backend/moyu_extract.py:905-910`）：

```python
    except Exception as error:  # noqa: BLE001 - 自定义 provider 崩了也不许拖垮整章
        # 非契约异常：原文可能带 Authorization/API key，只保留异常类型（可诊断），不写原文。
        _reject(
            "provider_error",
            f"provider 调用失败：{type(error).__name__}（异常原文已隐去，避免凭据写入报告）",
        )
```

- 因此**任意形态**的凭据（Bearer、`sk-`、AWS key、cookie、自定义 token）都不可能经此分支进入 detail——
  探针 B9 用 `api_key=AKIAIOSFODNN7EXAMPLE cookie=session=abc` 验证：detail 里一个字符都不剩。
- 诊断性保留：`reason` 仍为 `provider_error`、detail 里仍有**异常类型名**（`RuntimeError`）与固定说明文案；
  丢掉的是 message 原文（如 "quota exceeded"）——这是有意的取舍，报告里明示（§五）。
- 契约层同为「降级不抛错」：`raw = []`，整章继续，`rejected_reasons` 恰记 1 次（探针 B7）。

第二条改动（`except ExtractProviderError`，`:901-904`）是在 provider 层已脱敏之外的**兜底**：

```python
    except ExtractProviderError as error:
        # provider 层已脱敏过；这里再兜一层，防止自定义 provider 直接把凭据塞进 detail。
        _reject(error.reason, _mask_credentials(error.detail))
```

`_mask_credentials`（`:572-580`）只做两件事：`(?i)\bbearer\s+[^\s"',;]+` → `Bearer ***`；
`\bsk-[A-Za-z0-9_\-]{4,}` → `***`。**它不是 t70 F1 的关闭手段**（关闭靠「原文不落盘」），
而是对自定义 provider 直塞 detail 的附加缓解——这也正是 §一 F1 的边界所在。

## 五、误伤评估（t71 是否伤到正常诊断 / 既有脱敏）

1. **诊断性**：`reason` 不变；异常**类型名**保留（探针 B2）；`ExtractProviderError` 路径的
   状态码与上下文文案保留（C1/C4、E1/E6）。丢掉的是任意异常的 message 原文——这是关闭 F1 的
   必要代价，且 detail 里有明确文案说明「已隐去」，排障时不会误以为是空异常。
2. **既有脱敏路径零改动**：`_redact_detail`（非 2xx / content）与 `_redact` 未被 t71 触碰，
   探针 E1–E7 复验 t68/t70 的结论仍成立（跨界前缀不残留、网关 code 可见、单次请求）。
3. **误伤面**：`_mask_credentials` 会把形如 `sk-learn` 的**非凭据**词抹成 `***`（探针 F3）。
   影响仅限 `ExtractProviderError.detail` 的展示文案，不影响判定/计数；且该函数只在此一处调用
   （`grep -n _mask_credentials`：572 定义、903 唯一调用点）。记为**观察项**，不单列 finding。
4. **幂等**：重复掩码不产生 `Bearer *** ***` 之类叠加（F2）。

## 六、新问题

### F1（low）`ExtractProviderError.detail` 只掩码两种凭据形态

`backend/moyu_extract.py:903` 的 `_mask_credentials(error.detail)` 覆盖面是
`Bearer <token>` 与 `sk-[A-Za-z0-9_-]{4,}`；其余常见形态不被掩码，随报告 JSON 落盘：

```
provider = lambda t, c: (_ for _ in ()).throw(
    ExtractProviderError("bad_gateway", "HTTP 502：api_key=AKIAIOSFODNN7EXAMPLE"))
→ rejected[0].detail == "HTTP 502：api_key=AKIAIOSFODNN7EXAMPLE"
```

可达性：需调用方自备 provider 走**契约异常**并自行拼 detail（`OpenAIProvider` 全路径不受影响，
其 detail 已经 `_redact_detail` 按 header 全形态脱敏）。危害同 t70 F1：基准/报告产物持久化凭据。
性质：**非回归**——t71 之前该分支完全不掩码；本次是净增强，只是覆盖不完整。

**requiredFix**（任一即可）：
1. `_mask_credentials` 扩展常见前缀：`(?i)(api[_-]?key|x-api-key|token|secret|password)\s*[:=]\s*\S+` → `\1=***`，
   并补 `AKIA[0-9A-Z]{16}` 一类固定形态；
2. 或（更彻底）与 t70 F1 同构：`ExtractProviderError` 的 detail 也只保留「reason + 状态码/固定文案」，
   由调用方用结构化字段（已有 `payload` 参数）传上下文；
并补 fixture：自定义 provider 抛 `ExtractProviderError` 且 detail 含 `api_key=AKIA…` → 断言 detail 不含该串。
