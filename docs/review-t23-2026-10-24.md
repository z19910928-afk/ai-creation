## 4. Findings

### F1（medium）白名单放行「有谓词、没槽位」的 `has_attribute`，会诱发一致性引擎假阳

- 现象：`assertion_predicate({"predicate": "has_attribute"})` → `('has_attribute', None)`，`assertion_object()` 因槽位为空只写 `{name,type,note}`。同实体两条这样的断言（note 不同）落到引擎里，`_classify_object_conflict()` 走 `predicate != "has_story_fact"` 分支，判 **high**「has_attribute 存在冲突取值」，实测 `findings=1 score=92.0 grade=B`。
- 原因与归属：写入端（t23 的本文件）选择"信任白名单内谓词"，判断本身不算错；假阳来自一致性引擎对"无槽位 has_attribute"没有专门的退化分支。修复归属应为 `backend/moyu_consistency.py`（t24/t25 的写域），或写入端在槽位为空时把谓词降回 `has_story_fact` 并记一条事件。
- 可达性：需要模型在候选顶层写 `predicate="has_attribute"` 却给空/缺 attribute；`character_state` 候选由 schema 强制带 attribute，正常路径不会命中。
- 建议：取其一，不要两边都改——(a) 引擎把"两侧都没有槽位"的 `has_attribute` 按事实处理（与 `has_story_fact` 同分支）；(b) 写入端在 `attribute == ""` 时回落 `has_story_fact` 并复用现有 fallback 事件。

### F2（low）重锚 UPDATE 只刷新 predicate/object/evidence，不动 valid_start / valid_end / epistemic_mode

- `ensure_memory_assertion()` :4319 的 UPDATE 子句未包含 `valid_start`、`valid_end`、`epistemic_mode`。记忆被重新确认、时间窗或认知模式变了时，断言的 `object_json`/`predicate` 会更新而有效区间保持旧值，可能出现"取值是新的、窗口是旧的"。
- 不会静默产生错数据：`reuse_analysis_candidate()` :5613-5616 会拿 `valid_start`/`valid_end`/`epistemic_mode` 比对，不一致直接 409 让作者到记忆中枢核对。故定级 low。
- 建议：在文档里写清"重锚只刷新谓词与取值"，或把窗口一并纳入 UPDATE（注意 canon 触发器前置条件）。

### F3（low）`_normalized_json()` 对 NaN / Infinity 不收敛

- `_normalized_json(float("nan"))` → `("number", nan)`，而 `nan != nan`，因此 `same_json_value(nan, nan)` 为 False。`json_text()`（:187-188）用默认 `allow_nan=True`，Python 的 `json.loads` 也接受 `NaN` 字面量，所以理论上客户端可以造出这种取值。
- 现实风险很低（正文事实不会写 NaN），但会让"同一条断言与自身比"报冲突。
- 建议：把非有限浮点归一成哨兵值（如 `("number", "nan")`），或在写入端拒绝非有限数字。
