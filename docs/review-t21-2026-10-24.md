## 三、探针：`/tmp/review_t21_probe.py`（68 checks / 0 failed）

与 t33 的证伪写法不同：标记串带**随机后缀**；两次独立 run 用**不同长度**的标记并断言 `seed_characters` 的差量；再用**手工补 seq=2 分片**证明「按 seq 拼整条 run」而不是「只读第一片」；另加函数级单测与零调用边界对照。

要点：`_resume_seed_payload()`（`backend/server.py:1610-1622`）拒绝空/纯空白正文与缺失来源，但对合法正文**不 strip、不裁剪**（U1 最后一条）；`_resume_requirement()`（`backend/server.py:1645-1651`）的余量按 `max(0, target-seed)` 计算，不因 `round_target_ratio` 改口径。

### 3.2 零调用与边界（Z1/Z2）

```
PASS Z1 seed=lower 零次 provider 调用 | calls=[]
```

`target=600` → `lower=ceil(0.9×600)=540`。种子 540 时引擎在循环顶直接 `TARGET_REACHED`（`backend/moyu_continuation.py:734`），provider 一次都不调、`rounds=[]`、正文就是种子；种子 539 时**必须**调一次——证明阈值不是「差不多就算达标」的放水实现。

做法：假 SSE provider 让第 2 轮挂住 → 取消（`billing_state=usage_reported`，这是可重试的前置条件）→ 直接 `UPDATE app_ai_chunk` 给落盘正文追加只有库里才有的标记 → `POST /api/ai/jobs/{id}/retry`。三组标记的随机后缀不同、长度不同（`delta_a=15`、`delta_b=45`），`seed_characters` 的增量与标记字数一一对应；`resumed_from_run` 与 `consent.resumed_from_run` 都指回原 run。

RC 补分片用的是与写入端同形的 INSERT（`id/project_id/branch_id/ai_run_id/seq/text/payload_hash/cumulative_hash/created_at`），目的是让 `resumable_continuation_seed()` 的 `ORDER BY seq` 有第二片可拼——真实取消点只落 1 片时 `MAX(seq)=MIN(seq)=1`，无法区分「读全部」与「只读第一片」，这条把该盲区补掉。

## 五、findings

| id | severity | problem | requiredFix |

| F1 | low | 种子读取路径（`resumable_continuation_seed()`，`backend/server.py:1636-1642`）不校验 seq 连续、也不校验 `cumulative_hash`/`payload_hash`；写入端 `persist_ai_chunks()`（`backend/server.py:1199-1201`、`1211-1223`）是校验的，但若库被外部修补出缺口或篡改，读取端会**静默**拼出一段有缺字的种子，错误会以「模型接着写但前面少了几句」的形式出现，而不是报错。 | 二选一：①读取时断言 `seq == 1..n` 连续并校验 `cumulative_hash`，发现缺口抛错/退回无种子重放；②在 `resumable_continuation_seed()` 的 docstring 与 `docs/continuation-production.md` §8.2 明写「依赖 `persist_ai_chunks()` 的写入不变式，外部修库不在保证范围」。当前实现不算缺陷，属加固项。 |

补充观察（不构成 finding，记录以免误判）：

1. **真实取消点只落 1 个分片**：取消发生在第 2 轮传输中时，第 1 轮正文是唯一已提交分片，`MAX(seq)=MIN(seq)=1`；多分片拼接由 RC 手工补片验证（见 §3.3），不是实现缺陷。
2. **`resumed_from_run` 只记直接父 run**：嵌套重试时父 run 的正文里已含更早的种子，整体当种子不会重复计字（`docs/continuation-production.md` §8.2 的既定口径），本轮 RC 的 `seed_characters` 与库内字数严格相等可佐证「不重复累加」。
3. **`seed_characters` 是「非空白字符数」**（`moyu_output.count_characters`），与库里文本的字节/字符长度在含空白时不相等；对账要按同一口径，不要把 `len(text)` 当基准。
