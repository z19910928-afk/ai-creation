## 二、四条契约复现（自造探针）

探针 `/tmp/probe_t20_seed.py` 直接导入 `backend.moyu_continuation`，用一个假的 `generate(prompt_context, round_index)` 逐轮记录收到的 `prompt_context` 与调用序号，不依赖被测 fixture 的断言。结果：**TOTAL 95 / PASS 95 / FAIL 0**（exit 0）。

### 2.1 seed 计入 `characters`（契约一）

被测起点由 `count_characters`（`backend/moyu_output.py:134`，非空白字符口径）算出，见 `backend/moyu_continuation.py:658-659`；`total_characters = seed_characters`（`:662`）。

| 输入 | 实测 `seed_characters` | 第 1 轮 `prompt_context.characters` | `remaining_characters` | `characters`（返回） |
| --- | --- | --- | --- | --- |
| 无 seed（默认） | 0 | —（`prompt_context == {}`，旧行为） | —（同上） | **150**（3 轮 × 50，`max_rounds=3`） |
| 显式空串 `""` | 0 | —（同上） | —（同上） | **150**（同上） |
| `"  前导空白  " + "文"×97 + "  结尾  "` | **103** | **103** | **497**（= 600 − 103） | **253**（= 103 + 3 轮 × 50，`stop_reason=max_rounds`） |

- 103 = 前导/结尾的非空白字 4 + 2，加正文 97；seed 里的空白**不计数但原样保留**（见 2.2）。
- 无 seed 与显式空串两条路径逐字段一致（`text`/`characters`/`round_count`/`stop_reason`/`seed_characters` 全等），且第 1 轮 `prompt_context` 都是空字典——与 t20 前的旧行为一致。

### 2.2 非空 seed 时第 1 轮 `previous_text` 与 seed 逐字相等（契约二）

`backend/moyu_continuation.py:719-729` 把 seed 装配成「第 0 轮」记录后调用同一套 `_next_context`，`_default_next_context` 在 `:403` 做 `previous_text + str(record["text"])`（首轮 `previous_context` 为空字典），所以结果就是 seed 本身；`:434` 的 `remaining_characters = max(0, target − total)` 已扣掉 seed。

实测：`prompt_context["previous_text"] == seed`（含首尾空格的 seed 也**逐字相等**，探针用 `==` 而非 `in` 比较），`round_index == 1`；`"continuation_round"` 之类的嵌套键没有出现（第 1 轮仍是扁平键），与生产侧 `create_ai_job()` 的注入形状一致。

### 2.3 seed 已达量时零次 provider 调用并返回 `TARGET_REACHED`（契约三）

`:732-737` 把 `seed_characters >= lower` 的判断放在取消/预算检查**之前**并直接 `break`，因此不会有任何一轮进入 `generate`。

| 场景 | `generate` 调用次数 | `rounds` / `round_count` | `stop_reason` | `text` | `target_reached` | `within_tolerance` |
| --- | --- | --- | --- | --- | --- | --- |
| target 3000，seed 恰好 = lower 2700 | **0** | `[]` / 0 | **`target_reached`** | **等于 seed** | true | true |
| target 3000，seed = 3800（> upper 3300） | **0** | `[]` / 0 | **`target_reached`** | 等于 seed | true | **false**（如实越界） |

第二行同时证明「seed 未改容差定义」：超过上界不会因为走 seed 分支就变成「合格」。

### 2.4 非字符串 `seed_text` 抛 `ValueError`（契约四）

`:646-647` 在调度前做 `isinstance(seed_text, str)` 校验。探针逐个投喂 `None`、`123`、`1.5`、`True`、`b"bytes"`、`["a"]`、`{"k": "v"}` 七种非字符串：**七种全部抛 `ValueError`，且 `generate` 调用次数为 0**（失败发生在任何 provider 调用之前）。

### 2.5 纯空白 seed 降级为空（t20 自述的边界）

`" "`、`"   "`、`"\n\t"`、`"\u3000"`（全角空格）、`" \u3000\n\t  "` 五种输入：`seed_characters == 0`、第 1 轮 `prompt_context == {}`（与旧行为逐字节一致）、返回 `text` 没有空白前缀、`generate` 照常被调用。降级实现是 `:658-661` 的 `effective_seed = seed_text if seed_characters > 0 else ""`，纯空白既不计字也不进 `pieces`，所以不会在正文开头留下一段空白 + `\n\n`。

## 六、观察（低风险，不构成 finding，不影响 pass）

1. **docstring 提到 `round_metrics`，引擎实际返回 `rounds`。** `backend/moyu_continuation.py:562` 写「`rounds` / `round_metrics` 仍只统计本次新发生的轮次」，但引擎返回字典里没有 `round_metrics` 键——那是 server 侧 `_budgeted_round_metrics()` 从 `rounds` 派生的名字。审计时以 `rounds`/`round_count` 为准；建议后续把 docstring 改成「`rounds`（server 侧派生的 `round_metrics`）」以免读者去找不存在的键。属文档措辞，不改行为。
2. **`rounds[].cumulative_characters` 含 seed，`rounds[].characters` 不含。** seed 200 + 两轮 50 时，`rounds[0].cumulative_characters == 250`、`rounds[0].characters == 50`。这是「seed 当第 0 轮」的自然结果，也是 server 侧 `_budgeted_round_metrics(base_characters=seed)` 依赖的口径；但引擎自身没有一行注释说明这点，消费方若把 `characters` 逐轮累加再和 `cumulative_characters` 对照，会差一个 seed。建议在 `:862` 附近补一句注释。

两条都是可读性/文档精度问题，不涉及错误记账或错误行为，按「任何 high/blocker 一律 needs_revision」的口径，它们不达该级别，故判定 **pass**，仅记录。
